# Synthetic reference-school data

All people, schools, learning content and outcomes here are fictional technical fixtures. Human display names and class/year labels support a readable customer demonstration; they are not real pupil/staff/guardian records. Technical identity UUIDs and account addresses remain deterministic for authorization tests. `synthetic=true` remains authoritative for fixture isolation; removing “Synthetic” from a person label does not permit real data in development.

Root bootstrap applies seed.sql and provisions Auth identities from identities.json into ignored local credentials. Reference learner scenarios are generated by scripts/seed-reference-scenarios.ts from source-locked curriculum artifacts. Those artifacts remain synthetic and make no official curriculum claim.

Browser/API acceptance tests create additional records with test titles and random IDs. After the final acceptance run, reset only the guarded local synthetic Cuevo environment and reseed the reference scenarios before customer demo use. Never run that reset against a school database, and never scrub or rewrite actual customer-authored names to resemble demo content. Source77 defines fixture population/scenarios; no curriculum facts are invented by readable labels.

The primary reference-school seed explicitly enables the restricted-record capability for a technical synthetic demonstration; its factual-record policy remains absent/disabled until the human administrator reviews it. Other tenants do not inherit this entitlement. Synthetic-only retention wording is a technical operating basis, not a legal schedule or production approval.
