# Competitor Feature Parity Map

## Baseline goal

Edeviser should eventually cover the broad capability surface expected from a modern K–12 school platform.

## Capability groups

- students
- parents
- classes
- attendance
- timetable
- calendar
- communication

### Learning
- courses

- lessons
- resources
- assignments
- quizzes
- feedback
- portfolios

### Assessment

- criteria
- native result models
- reports

### Curriculum
- planning
- standards/outcomes

- versions

### Intelligence
- analytics

- personalization

### Engagement
- goals
- habit/development

- XP
- leaderboards
- community

### Quality
- evidence
- CQI
- accreditation

## Edeviser rule

Parity features support the business.

The differentiating layer is:
**evidence → learner state → intelligence → action → measured outcome.**

## Do not make feature count the roadmap

Roadmap priority is based on:
1. daily school value
2. core-loop dependency
3. safety
4. customer demand
5. evidence/learning intelligence leverage
6. implementation complexity
