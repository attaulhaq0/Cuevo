This continues the founder-authorized customer-readiness goal. It introduces no application, API, grading rule, grant, curriculum, processor or presentation feature. The current hosted access verifier remains a separate zero-domain-write gate.

## Current evidence and gap

The existing `tests/e2e/customer-browser-learning-loop.spec.ts` operates real visible customer forms for course preparation, activity completion, submission, numeric marking/release, evidence/state, demonstration analysis, teacher approval, practice, reassessment, outcome, Coordinator summary and Parent Portfolio publication/revocation. Its local credentials, fixed origin and test registration cannot be used directly by a hosted operator.

The deployed access verifier checks normal sessions and scoped recovery, but deliberately rejects domain POSTs and reports full-loop/customer acceptance false. Real hosted native original-command, audit/outbox, habit/state and outcome evidence must follow separately. Rendered components and local mirrored sessions do not establish managed Auth/Storage/Realtime acceptance.
