# Verification architecture and synthetic provisioning plan

Status: expanded founder-authorized work on 7 October 2026; implementation and source verification are in progress, with integration and managed execution unverified. The founder directed CI architecture first. The previously prepared focused schema/Auth source remains one bounded lane within this plan.

**Goal:** Give routine PR/main changes timely connected confidence, retain complete affected high-impact suites, run exhaustive daily/customer regression separately, and use truthful scope-bound evidence for eventual hosted schema/accounts and release.

**Architecture:** Existing `Cuevo verification` runs stateless/security once, PR CSS/Markdown one-owner routine or conservative complete affected runtime, and every integrated main's full SQL/all API/signed Edge/core Chromium staging profile. A separate workflow owns exhaustive daily/customer regression. Selected packaging is production web/Vercel API/Edge, replacing legacy Docker release-image builds. Protected PR/signed main and original operator owners remain; local profiles do not establish hosted delivery.

**Sources:** Founder instruction in this chat; [verification profiles ADR](../../decisions/2026-10-07-verification-profiles.md) and [focused provisioning ADR](../../decisions/2026-10-07-focused-synthetic-provisioning.md); product02/38/39/43/61/67/81/82/83 and existing worker/founder release boundaries.

## Constraints

- No curriculum/policy/migration bytes rewritten, application features, provider reset, new credential recipient or silent remote ingestion.
- One source-owned inventory/profile mechanism reuses the existing suite/artifact/runner owners.
- Keep required protected PR/main, signatures, independent source/QA reviews and exact original founder approval.
- Routine evidence records its complete selected inventory separately from full and hosted claims.
- Run complete affected suites for Auth/access/SQL/worker/CI changes. Unknown/shared change ownership broadens scope. Keep full SQL/RLS/grants in the initial routine profile.
- Actual source/run/attempt/job proof and current main are re-read before release effects. Scheduled/general regression can never become customer-candidate authority.
- Original uncertain migration/account/provider intent remains review; no new key/package, reset or erase-and-repeat recovery.
- Reuse reviewed daily/watchdog source by mapping its workflow/job contracts first; do not copy the old `ci.yml` target unchanged.
