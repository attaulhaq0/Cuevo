# Course-scoped curriculum objectives

**Goal:** Two assessments in one programme-bound course can use two explicitly approved hierarchy objectives from the same exact pack version and subject. Keep the programme binding and all historical native result/evidence identities fixed.

**Sources:** Product05/06 versioned reference hierarchy and native semantics;13 course/assessment configuration;17 immutable objective/result source;34 curriculum golden cases;69/76 source-lock and review;83 MVP native academic/evidence chain. Existing approved synthetic primary artifacts establish technical context only. No official pack import, lifecycle activation or rewritten curriculum artifact is included.

**Design:** Add an immutable per-course objective approval mapping, initially populated from each existing programme binding and populated for future bindings by a trigger. Its source reference and generated approved School Custom academic reference remain distinct identities, linked by foreign keys. An admin/coordinator explicitly approves an additional objective/outcome/criterion with a reason and expected objective-list version. The command locks the course before checking versions/replay, validates current entitlement/role/class and the pinned synthetic VERIFIED/PERMITTED pack, and requires the new reference to share the original reference's nearest subject ancestor in that exact pack. Every explicit subject/year value in both ancestry paths must agree with the course/programme; contradictory or missing hierarchy scope fails closed. Legacy bindings without a subject ancestor keep their original approved objective but cannot gain further objectives by treating null as a wildcard. No course rebinding, source mutation or historical record rewrite occurs.

**Read/UI:** A private bounded course-objective page returns approved and eligible unapproved references with names, description, subject/year/programme/version context and an approval-list version. Curriculum UI exposes this page under a selected bound course and requires human confirmation/reason. The assessment preparation and academic linking choice queries use a private course-scoped academic-reference page; programme-bound courses offer only exact approved mapped references, while unbound School Custom courses preserve existing approved-reference behavior. Database assessment trigger enforces the same mapping even if callers bypass UI.
