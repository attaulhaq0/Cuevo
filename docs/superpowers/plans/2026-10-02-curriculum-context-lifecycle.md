**Current versus historical:** ACTIVE contexts permit new programme/course/learner/objective/plan configurations. SUPERSEDED contexts block new configurations but preserve existing current exact programme/source reads, normal submissions/marking and historical evidence under current enrollment/role/relationship authority; supersession alone is not revocation. RETIRED contexts block new configurations and learner academic work, while authorized retained historical evidence/native reports remain available according to a purpose-specific historical read policy. Never globally replace programme_course_allowed with an ACTIVE-only check because that also gates historical evidence; introduce separate configuration/write versus retained-source predicates with explicit consumers. Existing ongoing assessment/current source behavior and repair paths must be documented before implementation.

**Supersession:** A replacement context is a separately immutable exact source/version. Supersede links old→new only within the same source family/programme ownership and reviewed scope, with no automatic course rebinding, learner migration, objective mapping or curriculum inference. Teachers/admin explicitly configure new courses/programmes; existing results keep their original context. A supersession preview names both versions and affected bound programmes; customer-facing labels use real framework/programme/version dates, not IDs.

**Retirement:** Require explicit preview/confirm and reason after enumerating bound live courses/learners. Either refuse retirement while open academic work remains, or require a reviewed explicit recovery/closure policy; do not silently strand current learners. The smaller first increment should refuse retirement until affected open work is resolved, preserve historical read authority, and permit existing synthetic legacy contexts to continue. This is a scoped technical policy choice to review with root against source17/83, not an invented official curriculum rule.
