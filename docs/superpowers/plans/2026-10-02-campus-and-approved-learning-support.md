# Campus context and approved learning support metadata

**Goal:** Add the missing school campus context and private, explicitly approved learning-support/accommodation records for an individual learner/current assignment window. Keep identity/enrollment, academic evidence and sensitive support metadata separately authorized. Root owns student profile/learner goals; this slice does not duplicate them.

**Sources:** Product14 MVP campus entity and separated approved support/accommodation metadata;13 assignment accommodations;07 configuration/modularity;38 audit/idempotency;39 current role/relationship/purpose/private data;83 supported learning/parent boundaries. Sources do not define medical diagnoses, legal entitlement categories or official curriculum accommodations. Store only school-authored support instruction/approval facts with an explicit scope; never infer psychological traits or grading consequences.

**Campus:** Add school-owned campus records with human name, optional school-provided location text and active/retired state; bind a current class to one explicitly reviewed campus through immutable assignment revisions. Campus is an operating context, never a tenant or hard-coded school branch. Current staff class selectors/read screens can show the authorized campus name; unknown/unassigned campus is a localized unavailable state. Campus retirement refuses currently assigned active classes until the school explicitly moves/unassigns them. Important campus/assignment changes require admin reason/confirmation, expected revision, idempotency/audit/outbox; no implicit access grants from campus membership.

**Learning support:** Private immutable school-approved learner support records scoped to an exact current learner/course or assessment and an effective date window. Fields: human title, plain instructional support description, school approver/reason/date, status/current revision and learner-facing instruction separately from private approval note. No predefined diagnosis/category/character score, legal eligibility, extra grading thresholds or AI-inferred needs. Admin/coordinator records human approval; teacher may read only a currently assigned course/learner's instructional support required to teach that task. Students see only deliberately published own assignment instructions; parents require separately explicit current approved sharing. Neither public availability nor UI hiding grants access.

**Scope:** Verify current tenant/entitlements/session/role/class/course/learner enrollment/programme before every read/mutation/replay. An assessment-scoped record must belong to that exact course. Effective windows use explicit ISO dates; expired/revoked/unknown approval does not become active. Retained support audit is restricted to authorized staff, with current learner purpose; no raw support table/Data API/AI/worker grants. No added grade, access, curriculum mapping or medical authority. Parent revocation/current sharing follows exact guardian/source scope and held-byte protections where relevant; no broad unrestricted profile object.

**UI:** School operations owns campus management and scoped support metadata forms, using actual class/learner/course/assessment names and current access revisions. Instructional support appears in the exact supported task view only after server scope checks; approval details require an explicitly opened staff disclosure. Empty/denied/unknown/expired states are localized. EN/AR/RTL/mobile/keyboard/axe/console/shared retry/current session cancellation required. Do not display sensitive support on general class cards, student-quality dashboards or model context automatically.
