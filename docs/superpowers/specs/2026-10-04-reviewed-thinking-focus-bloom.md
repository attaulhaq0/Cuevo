# Cuevo reviewed thinking focus (Bloom) integration

Status: founder-authorized extension on 4 October 2026; implemented through existing owners and locally verified in the isolated synthetic runtime. See the [verification report](../../reports/2026-10-04-reviewed-thinking-focus-verification.md) for evidence, retained intermittent conflict, capacity limits and hosted/integration gates. This replaces the prior proposed-only status. The separate backend checkout and database remain untouched.

## Pedagogical meaning

Use the revised cognitive-process categories Remember, Understand, Apply, Analyze, Evaluate and Create to describe the demand of a specific task. A primary focus and up to five distinct additional focuses support mixed tasks. Categories are not ordinal learner levels, task difficulty, mastery scores, grade bands, XP tiers or enforced prerequisites. Existing unclassified learning remains usable. No automatic verb classifier, grade mapping or whole-curriculum adaptive engine is introduced.

A versioned local vocabulary records structural category identities, bilingual Cuevo-authored plain-language descriptions and references. The 2001 Anderson/Krathwohl complete edition and Krathwohl 2002 overview (DOI10.1207/s15430421tip4104_2) are bibliographic anchors; full text is closed/unavailable and is not copied or claimed licensed. University of Florida's teaching guide corroborates all six categories; Iowa State's current CELT page corroborates the revised framework. Sources are research evidence, not official curriculum rules. Store dates/digests/reference metadata and short original descriptions rather than protected diagrams/tables. Each school classification requires explicit human review of actual instructions/material and rationale. Knowledge dimensions, mastery thresholds, automatic prerequisites and AI tagging remain future separately reviewed scope.

## Ownership and state

Curriculum owns the immutable vocabulary artifact and a narrow public catalogue validator; School Learning owns exact activity/assessment/criterion mapping drafts, review revisions, current projection and source snapshots. Assessment/native grade ownership remains Academic. Public strict schemas live in @cuevo/contracts; feature UI stays Learning and consumes the shared tokens. Curriculum provides a current course review entry using Learning's public UI, without a second authoring application.

Teachers/admins author only within their existing managed course. Coordinator/Admin reviewers require current learning/curriculum scope and a different actor from the author. Every draft/review/replay checks tenant, entitlement, role, current source, revision, course and object scope in API and private SQL. Self-review is denied. Mapping edits and decisions create immutable revisions and retain original author/reviewer/date/reason. Withdrawals affect current presentation while existing completion/submission/evidence snapshots remain unchanged.

Activity mapping pins exact immutable content revision; assessment/criterion mapping pins preparation/policy plus rubric/version/criterion identity. A content or assessment revision change invalidates current classification until re-reviewed. Publication creates a new content revision; copy only explicitly approved same-content mapping provenance to the exact published revision through a reviewed immutable lineage, never silently inherit changed content. Old records stay unclassified, never default to Remember. Parent reads use existing exact child/result publication authority.

Important mutations commit mapping/review, audit and durable outbox together. Reads use tenant/course/source indexes and bounded pages/sets; no model call or full-school recomputation per click. Existing outbox processor validates and acknowledges this metadata event without changing academic/XP state. Completion/submission capture current approved mappings in an immutable snapshot. Current result-context reads use existing native-source authorization before exposing snapshots.

## Customer experience

Author/reviewer sees exact task instructions, selected categories, rationale, version and unchecked confirmation. Student sees a concise personalized task message such as 'Use an idea in this activity', with an optional explanation and reviewed metadata. Reviewable focus is separate from completion/feedback/practice/reflection/growth navigation. Parent sees it only with authorized published evidence. Every view preserves existing submit/complete/mark/release/approval action, unknown states, private files, EN/AR, RTL/mobile/focus/reduced motion and the approved authentication.

Staff inspection resolves a complete exact-source material manifest and purpose-specific byte delivery through existing private storage. Coordinator inspection is limited to current learning/curriculum course review scope; it does not grant general resource enumeration or download. Source version, target/resource/revision, asset state/hash and current identity are checked before and after byte delivery. Unconfirmed manifests stop a new approval; the API/private command also requires a complete available manifest before creating an approval. Rejection, withdrawal and original-command reconciliation retain their existing safe recovery behavior; an explicit human confirmation records the review decision without claiming download telemetry proves reading. Material replacements invalidate the classification source as other source edits do.

## Verification gates

Use a separate local synthetic Supabase runtime and explicit local API/web ports; never apply migrations to the backend chat's database or reset/reseed its environment. Source-lock tests, strict contract tests, private SQL/RLS/grant deny tests, actual Auth/API/Postgres atomic/replay/source-change tests and browser author→review→learner→submission→native release→parent read must pass. Confirm numeric zero/full rubric semantics, immutable historical snapshots, role/enrollment/publication revocation, no XP change, absent metadata compatibility, bounded page performance and existing learning/native academic regressions. A rendered tag or unit pass is not end-to-end acceptance. Record failed/missing gates honestly.
