## Chosen boundary and alternatives

Use one native-owned phased admission. Replace native admission's duplicate Management inventory query path with fixed metadata SELECTs on the already held Client; overlap only the bounded Storage HTTP comparison reads with those serial native reads. Validate all sources/metadata/bytes and drain every sibling before publishing the existing opaque permit. Do not lengthen30s, restamp clocks, accept callbacks or change original uncertainty.

Rejected: blindly parallel existing native and inventory helpers opens mgmt-api postgres work across quiescence. Moving inventory before native simply ages its proof across official/native work. Extending freshness or retrying changes the safety policy without removing duplicated observations. Reusing unbound caller inventory/target JSON would replace real admission with metadata.

Existing ownership remains: hosted-migration-database.ts holds Client/lease and native registry; hosted-operator-storage-observation.ts owns pure metadata normalization/agreement and source policy; hosted-operator-storage-inventory.ts retains its existing ordinary Management reader and forwards comparison interfaces; hosted-migration-storage-observation.ts owns one fixed bounded Storage transport/chain decoder; hosted-migration-remote-journal.ts retains the effect-capable journal factory and forwards comparison interfaces; hosted-migration-executor.ts owns exact stage/source/package consumption. No new database, task ledger, credential system or generic transport is added.

## Fixed APIs and facts

Add a read-only sibling of the existing remote journal factory:

```ts
observeHostedMigrationStorageProject(input: {
  projectRef: string;
  boundProjectRef: string;
  storageKey: string;
  signal: AbortSignal;
}): Promise<HostedMigrationStorageProjectObservation>
```

It accepts neither providerToken, SQL, callbacks nor evidence input. It can only GET the fixed operator bucket and INFO/body paths and POST fixed paginated LIST requests. It exposes no write/readJournal/permit method. Extract one private fixed read-only collector for bounded Storage transport and chain metadata; both the existing effect factory and this Storage-only observer consume it without duplicate implementations. Its fixed bucket-admission mode selects Storage-only metadata versus existing Management+Storage admission internally; callers supply no function or query. It reads bucket metadata and exact complete operation lists before and after every bounded chain scan. Observation includes actual began/completed clocks; bucket id/name/private/type presence/limit/MIME values; sorted operations/owner/record bytes; each object's INFO id/path/size/content_type/version presence; body hash/length and listed metadata. It must preserve whole-project/chain ordering, gaps, malformed/oversize/redirect/UTF8/foreign paths, atmost8active requests and complete sibling settlement. Type omission stays explicitly missing until actual native metadata proves STANDARD; it is never defaulted.

Initial reconciliation and continuation publication invoke the same private phased collector before registering a permit; public refresh only repeats that collector for an already registered identity. Getter returns a clone only after the registered opaque permit/current identity/live TLS/lease/package/absolute expiry/each original observation age passes. ## Exact phases

1. **Authority and source before observation.** Verify current registered identity/allowed cursor/live lease, clear the prior pair, await the existing complete official admission, revalidate absolute expiry/TLS, and admit current physical stage/source bytes. The existing journal/source-only local checks and provider endpoint selection can finish here; they perform no catalogue-conflicting SQL. This admission does not call provider deployment or journal writes.
2. **Native PRE metadata.** Capture the original cohort begin. On the held Client only, execute one fixed parameterized JSON snapshot SELECT per PRE/POST phase for all Storage buckets/counts, all operator-object metadata and current target counts/schemas/roles/school/auth facts; include id/name/bucket/version/size/MIME and exact UTC microsecond creation/update times. Read current history, source-bound target counts, runtime roles/schemas and required private controls. Reject any extra application file, invalid path, unknown type, count/identity mismatch or wrong stage. This is comparison input, not execution permission.
3. **Storage-only and serial native lanes.** Capture provider metadata by the existing actual readHostedMigrationProvider with the bound direct/session endpoint before the cohort; retain that original provider time. In the native cohort, perform the first quiescence check before starting Storage-only requests. Start observeHostedMigrationStorageProject with the lease AbortSignal, then run a fixed internal catalogue phase on the same Client: repeatable-read read-only structural/authority/history and native target/private/post facts. Its final ROLLBACK/history/quiescence phase occurs after Storage drain below; the ordinary public readSchemaCatalogue operation remains unchanged. No Management query or second Client may run in this cohort, including hidden remote factory bucket admission. Native queries are not Promise.all on one Client. The catalogue PRE/POST pg_stat_activity predicate remains unchanged, with final evaluation correctly sequenced after lane drain. Source/request clocks describe real work; preserve30s and absolute expiry. Offline tests first retain refusal for any forbidden postgres activity. Hosted Storage backend role/quiescence is an execution-time observation; if conflict is present at the required quiescence phases, refuse rather than ignore it. Its unknown role does not prevent implementing the conservative source guard.
4. **Drain and native POST.** Await both lanes with allSettled; failure cancels admitted HTTP through the shared signal and waits for its bounded active/queued/body reads to finish. Only after full settlement finish the fixed catalogue ROLLBACK/currenthistory/finalquiescence phase, then execute held-Client POST bucket/object metadata/count SELECTs and native identity/history/private-state rechecks. No earlier final quiescence check runs while Storage requests remain active. Apply a final physical source/stage identity check. Successful observations require confirmed read/cancellation settlement. A rejected or unacknowledged cancellation refuses publication; its bounded returned failure is not evidence that an uncooperative underlying transport completed cleanup. Native SQL rollback/lease release remains separately observed and cannot be relabeled as successful HTTP drain.
5. **Agreement and publication.** PRE and POST metadata must be exact equal ordered snapshots; Storage bucket values match the native bucket including explicit int8 text conversion; listed/object INFO id/path/size/MIME/version matches native rows; body bytes match every owner/record and required original immutable journal exactly; counts/set/hash have no missing/extra objects. Reconciliation's one exact original UNKNOWN/REVIEW exception, prior committed continuation/batch coverage, current owned intent, source-backed cumulative history, disabled private capabilities and immutable receipt readbacks retain their existing predicates. History/target/postconditions gathered from the actual native lane must agree across phases and with source-derived expected versions. Require every original official/native/Storage/source observation within30s and package not expired. Only then store the fact pair/permit clock.
6. **Consume and effect.** Executor uses readNativeSchemaStageAdmission instead of separately rereading target/postconditions and rerunning ordinary Management inventory after native refresh. Retain all existing semantic source/package/TLS/history/inventory cross-checks against the paired actual facts. Refresh the complete cohort for executor revalidate and each original CLI/batch consumption. Ordinary journal INTENT/COMMITTED retains the existing smaller native-only refresh and actual paired authority check, so a≤22s complete cohort is not followed by~10s journal I/O under the same short lease. Native-only refresh clears optional complete facts but leaves its successful NativeAuthorityPair; the full getter requires newly complete facts. Do not refresh safety REVIEW or reinterpret UNKNOWN. Last local artifact/certificate/native process checks still apply. Journal compare-and-write keeps its full immutable PRE/POST checks and may still legitimately expire; no generic automatic retry is introduced.

Reconciliation receipt persistence continues its existing newly observed proof/create-only/readback rule; after readback, fresh authority/cohort publishes the permit while original receipt bytes/time remain unchanged. Continuation refresh uses actual original completed/private chains in the Storage observation and existing source-derived batch bounds; current INTENT ownership is still accepted only after exact dual acknowledgement. The new observer returns metadata for all chains; only the native owner grants the one original-review exception.
