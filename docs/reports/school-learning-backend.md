# School and learning backend verification

Date: 1 October 2026. Company: E Deviser. Product: Cuevo.

The backend now persists school-authored course → unit → published lesson → activity → student completion, and teacher-defined numeric assessment → immutable student submission. It uses the existing verified Supabase identity/current-session boundary, Nest/Fastify controller, private PostgreSQL schemas and actor/school transaction helper. Academic marking, results, curriculum mapping, evidence release and intelligence remain later work.

## Contract and implementation

`createSchoolLearningController(identity, database)` exports the controller factory in `apps/api/src/school-learning/controller.ts`; root integrated it into the existing app. `packages/contracts/src/school-learning.ts` provides strict bodies, bounded pagination and command-key schemas. GET classes, people, subjects, courses, assessments and submissions return `{items,nextCursor}` with UUID keyset pagination and a maximum limit of 100.

All POSTs require an 8–200 character Idempotency-Key. First and replay return HTTP 200 with the original stored JSON response. Request fingerprints include command, path target and normalized strict body. Before reading a replay or writing a command, a current database check validates the target relationship and required entitlement. Result, audit, outbox and stored replay response share one transaction. Failed writes roll back their reservation. Event deduplication keys are hashed rather than truncated.

Teachers author only their currently assigned class/subject and their own course; admins use current school scope. Courses begin DRAFT. Explicit `POST /v1/courses/:id/publish {}` enables student/parent content access through active current class relationships. Archived classes deny course content. Lessons are published school-authored content but remain hidden until the course is published. Students complete/submit only as their own auth subject with current enrollment. Parents cannot submit or access raw submission queues. Coordinator read access follows the contract; coordinator submission queues are denied.

The assessment maxScore is an arbitrary positive teacher-defined numeric maximum bounded for technical safety, with policyVersion 1. No official threshold, grade conversion, syllabus code, attainment mapping or regulatory assertion exists.

OpenAPI declares strict POST bodies, required idempotency headers, current-school selector, pagination parameters, response shapes, shared errors and the detail size error. A generated-document test exercises that metadata.

The current nested detail contract is bounded to **100 total unit/lesson/activity nodes and 500KB of serialized lesson/activity content**. Queries use sentinel limits; overflow returns `LEARNING_DETAIL_TOO_LARGE`/413 with no partial-success response. This is a temporary capacity boundary for the small vertical slice; larger-course navigation requires a future paginated detail contract.

## Database migrations

All migrations were generated by the Supabase CLI and applied using `migration up --local --network-id cuevo-local`, preserving existing local Auth. No remote mutation or local reset was performed.

- `20260930235603_school_learning.sql`: seven tenant-safe tables, RLS/read/write scope, immutable completions/submitted revisions and explicit private grants.
- `20261001000056_school_learning_visibility.sql`: INSERT RETURNING regression fix. Course SELECT checks the row directly because a stable self-query cannot observe the row being inserted.
- `20261001000305_school_learning_scope_guards.sql`: current active-class guard and permission-scoped private parent-resolution helpers.

Fresh synthetic seed adds `learning` and `assessment` entitlements. The already-running local synthetic tenants received the same explicit additions through a localhost/56322 checked update. No customer entitlements were inferred.

The real local integration scenario signs in through Supabase Auth and uses the actual Nest controller and constrained runtime PostgreSQL connection. It proves teacher hierarchy authoring/publish, enrolled-student activity completion, numeric assessment/submission, exact replay, changed-input conflict, duplicate revision denial, unassigned teacher, unrelated student, parent and foreign-tenant denial, malformed body/key/query denial and failed-command rollback/retry. It revokes the authoritative teacher assignment/enrollment after successful commands, checks replay denial through HTTP, and restores fixtures in `finally`.

Pure regression cases additionally assert scope is checked before a completed reservation is read and an oversized tree returns explicit 413. SQL cases verify private Data API grants, current revocation/archival, immutable revisions and direct helper scope.

The integration suite conditionally skips when a local environment is absent, suitable for unit-only CI stages. A release/integration gate must set `CUEVO_REQUIRE_INTEGRATION=1` after local bootstrap so unavailable fixtures fail rather than skip. The successful local run above did not skip. Do not run local SQL and the integration suite concurrently: the integration suite deliberately changes authoritative revocation fixtures briefly. The outbox recovery SQL test isolates pre-existing synthetic events inside its rolled-back transaction so prior real API runs do not corrupt fixture counts.
