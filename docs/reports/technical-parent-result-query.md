# Bounded parent native result read

Date: 2026-10-01. Scope: current approved parent numeric/rubric result pages and academic command replay after source transitions. Sources 13/17/18/38/39/43/61/81 apply; the permission model is unchanged.

The accumulated synthetic dataset exposed an actual 503 from the default five-second SQL statement timeout on /v1/results for a current parent. This was not a missing first-page assertion. Read-only EXPLAIN ANALYZE under the actual parent actor/current school showed repeated current-result RLS correlated subqueries and poor joins before the final page limit. One full native query took 2,219 ms and roughly 63,826 shared block hits; a naive additional parent relationship filter made it worse at 11,860 ms with more than 1.24 million rejected join combinations. The plan multiplied 24 current numeric rows by 18 visible references before exact result lookup and separately considered 120 assessments times 18 references in the rubric branch. Costs/times vary by warm cache/load; these explain observations establish the source of work rather than a general benchmark.

CLI-generated additive migration 20261001091326_bounded_parent_native_results.sql adds one private parent-only source read. It verifies current academic entitlement/role/tenant, resolves effective approved parent-child/student membership relationships, resolves enrolled published course access through the existing authorization helper once, reads only current parent-visible numeric/rubric source rows, verifies immutable evidence and approved exact reference version, bounds the combined set to page limit plus one before projecting title/native JSON, and applies a 500KB response cap. It accepts only a maximum 100 page size and cursor; caller cannot supply tenant, child or visibility. Only cuevo_api can execute it. Existing table grants/RLS and other-role query paths remain unchanged.

AcademicService routes only parent result lists through this function. Both models keep native data; rubric emits no scalar score. Same current guardian/source visibility remains required on every read. Mark/release authorization now also requires current_submission_open before returning stored receipts. Returned, closed or superseded sources cannot replay an academic command; historical evidence reads retain their original authority path.

Regression-first pure tests failed against the old result query and historical-only command authorization, then passed. Targeted 16 academic/rubric/current-read tests, root TypeScript, scoped lint and API build passed. Root applied 91326 with its source evidence predicates confirmed and reported the full SQL suite passed 332 assertions, including SQL047 parent-only, numeric zero, private release rejection, native rubric, page sentinel/cursor, revoked relationship, foreign school and explicit execution denial. Lifecycle API regression retains prior mark/release keys across return/resubmission/close and requires denied replay while old evidence remains visible. Root owns its actual combined API execution.

Post-change read-only EXPLAIN ANALYZE ran after the SQL mutation window, using the same current parent and unchanged statement_timeout 5000. The 25-row page executed in 375.688ms (9,177 shared hits), and the 100-row page in 403.303ms (6,825 shared hits). A confirmed 100-row request returned 30 rows: 24 numeric and six rubric, no scalar rubric fields and no next cursor. This is approximately five times faster than the observed former full query and avoids the pathological parent-filter plan. Timing varies with host/cache/load; authorization and bounded real data behavior are the acceptance assertions, rather than a fragile unit timing threshold.
