## Recovery review correction

An independent review identified that generic database/COMMIT receipt failures were being mapped to definitive INTELLIGENCE_UNAVAILABLE and that a failure write without a confirmed receipt could be ignored. A committed proposal might then exist while the browser cleared its original key. The corrected service returns INTELLIGENCE_OUTCOME_UNKNOWN for unconfirmed start/completion/failure persistence and never attempts a late failure write after an uncertain proposal commit. A provider/schema/timeout/budget rejection is definitive only after the failure transaction commits. Controlled SQL source/policy/authorization rejection remains explicit denial/review. COMMAND_IN_PROGRESS retains original-key reconciliation semantics.

Three recovery cases failed before remediation. The final service suite passed 11 cases, including proposal COMMIT receipt loss, failed failure receipt, uncertain start receipt, active-run reconciliation and current session/source denial. Typecheck and targeted ESLint passed. This correction edits no migration and performs no database mutation; integrator and independent reviewer own real recovery acceptance.
