## Security evidence and applicability

Source61 critical technical rows map to SQL005/010/020/030/035/040/045/047/050/060/062/065/070/075/080/085/090/098/100/105/110/115/120/125 and the real API suites. Tenant/guardian/teacher/class/programme/source/replay denials are separately exercised from frontend visibility. Storage uses private staged bounded bytes, integrity readback and current authorized reads; delivered bytes cannot be recalled. Realtime tests use actual sockets with peer/parent/foreign/public and revoked-session/roster denial; content remains API-authorized. Models cannot execute grading/access tools, invent citations or turn retrieved instructions into policy.

SQL injection protection uses parameters and strict contracts; content/report rendering is text/escaped HTML with no executable imported scripts. CORS is explicit; API requests use an in-memory bearer token and omit ambient credentials, so cookie-session CSRF is not an active command mechanism. Authorization still applies when an attacker sends a direct request. Process-local read/write/address budgets and community limits are tested; production gateway limits remain deployment policy. HTTP/database/worker telemetry has fixed fields and excludes sensitive request/error/body/query/token data. Runtime dependency and database advisors supplement the source-level checks and denial tests; they are not a security certification.
