# Current-school operations frontend

Date: 2026-10-01. Cuevo by E Deviser. Scope: Technical MVP Task 3 frontend under source 07/14/18/36/37/39/43/61/63 and frozen school API contract. No API, SQL, shared contracts, credentials, tenant bootstrap or app shell/layout edits were authored by this worker.

The owned school feature separates setup, people/access, daily operations and policy approval. Admins configure the current school details, academic year/term/year group/class/subject; pre-provisioned verified people roles/status/windows; enrollment, teacher and current guardian relationships. Access changes require explicit approval payload and server authorization. Read surfaces show actual memberships and relationships with their status.

Teachers record current assigned learner attendance; admin records/corrects it with revision/reason. Attendance is an operational fact and missing records are not absence. Admin configures timetable/calendar/report-period records. Students and parents use only authorized readonly attendance/schedule projections, with parent context requiring school approval; staff notes/access controls are excluded. Policies show configured sharing/recognition/leaderboard/analytics flags and require explicit version/reason/approval. Direct student messaging remains false; no live intelligence readiness is inferred from school flags.

The feature uses bounded query/pagination, bilingual copy, logical token CSS, semantic scrollable tables/forms/status, current session and original-key retry infrastructure. Root composes SchoolWorkspace and imports styles through its public ui/copy surfaces. No card-wall dashboard or broad all-student data object is introduced.
