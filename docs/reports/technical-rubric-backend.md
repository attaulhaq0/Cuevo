## Interface and storage

POST /v1/rubrics accepts courseId, title, version and 1–30 criteria with stable keys and 1–20 allowed named levels, each with description. Definitions are immutable; a changed definition uses a new version. GET /rubrics and /rubrics/:id return only current course-authorized definitions. Parent cannot retrieve internal definitions or authoring.

POST /assessments/:id/rubric accepts rubricId and expectedPolicyVersion. It pins a same-school/same-course version, sets rubric model and increments policy. No numeric/rubric draft may already exist. Used native assessment context and rubric assignments cannot change. The original numeric assessment maximum is retained privately for legacy schema compatibility and omitted from rubric academic responses; it has no native rubric meaning.

POST /submissions/:id/results accepts either the unchanged numeric score payload or nativeResult type rubric with rubricId and criterionKey/levelKey choices. The private source command requires an approved academic reference, exact pinned rubric/policy, latest marking revision and immutable source-submission evidence. Missing, duplicate, unknown or foreign criterion choices are rejected without default levels. Every required criterion must be explicitly marked. The source resolves and snapshots labels/descriptions in definition order.

The existing result release endpoint dispatches by numeric/rubric source table. It atomically creates immutable result/evidence/current pointer, while the actor transaction stores audit, canonical outbox and idempotent response. Same-key replay and new-key semantic duplicate release preserve one result; correction creates a new revision and keeps prior evidence. Numeric result score/max/native fields stay intact. Rubric current released responses contain nativeResult with type, rubric identity/title/version, policyVersion, normalized null and criteria containing criterionKey/title and chosen levelKey/label/description. Student sees their released native result; parent requires explicit parentVisible human release and a current relationship. Evidence exposes provenance without raw submitted content.

Tables: rubric_versions, assessment_rubrics, rubric_marking_revisions, rubric_result_revisions, rubric_evidence and current_rubric_results. All use tenant composite relationships, forced RLS, private grants and immutable history/definition triggers. Runtime API gets SELECT and constrained command EXECUTE only; worker/Data API roles have no raw table privileges. SQL functions have fixed empty search paths. Existing numeric improvement baselines cannot address companion rubric result IDs and therefore reject rubric comparison without a distinct comparable policy.
