# Event-triggered worker foundation

Status: accepted direction on 2 October 2026; locally implemented and verified, hosted activation and representative load remain pending. The founder explicitly requested a scalable event-triggered foundation for the MVP and full-app progression. Sources 01/02/11/38/39/65/81/82/83 continue to govern scope, authority and acceptance. The architecture plan records the phased extension path and qualitative comparison; neither authorizes post-MVP scope or certifies production scale.

Keep the existing durable transactional outbox and SQL domain processor. The candidate adds a coalesced transaction-committed `pg_net` wake, a bounded authenticated Supabase Edge adapter and due-work recovery scheduling. Retain Node worker execution locally. The [architecture plan](../architecture/scalable-event-processing.md) defines ownership, permission, lease, privacy, cost/latency, retention and acceptance boundaries.

Choose Edge execution over an initial direct SQL Cron driver because separate claim/process/failure commits more closely match the current worker contract. A direct SQL loop could change rollback/retry behavior or run with owner identity; any later stored procedure route needs its own proof. The Edge candidate uses a real restricted worker login, timestamp/wake-bound HMAC-SHA256 authentication before DB and the existing private domain processor. Local serving and Deno2.1.4 frozen14-package version/integrity parity with root npm passed; hosted TLS/role/secret configuration and hosted bundler refusal of a changed lock remain unverified.

Provider-owned local `net`/Vault grants did not become private through ordinary migration revokes. A guarded local provider-owner hook is required after bootstrap replay, and activation/dispatch now fail closed on unsafe schema/table/column permissions. Hosted activation requires Supabase Support or authorized owner hardening and actual privacy evidence. No runtime or migration credential may auto-escalate or substitute for that prerequisite; the network queue contains one-use signatures rather than the reusable key.

The wake is not authoritative storage: `pg_net` network state is unlogged/temporary. Lost wakes are recovered from the existing outbox. Coalescing state tracks an invocation generation/lease, not another list of domain tasks. The one-minute database recovery check runs even when idle and invokes Edge only for eligible work. Capped backoff applies to synchronous enqueue errors and admitted review/no-progress receipts; asynchronous delivery failures currently rely on expired-generation recovery without increasing that counter. No model-per-click or instant 10-second completion guarantee is accepted. Pause blocks new admission, not immediate cancellation of admitted work; generation coalescing does not establish a hard total concurrency/fairness limit. Event leases and source idempotency remain the write-safety boundary.

The Edge candidate resolves the sequential-batch lease risk through single-event claims, at most10 events, a20-second processing deadline and a15-second reserve before another claim for existing5-second claim/process/failure budgets. Event leases remain30seconds and the separate invocation lease remains60seconds from issuance. The30-second `pg_net` transport timeout is separate; connection, health/admission, finish and cleanup mean the processing deadline is not a total HTTP bound. Node tick defaults and per-event commits remain intact.

This is an execution-adapter change inside the modular monolith, not a new domain/microservice or general multi-industry agent platform. Required README/maps/scoped instruction/configuration/test discovery changes belong with implementation. Generated Supabase function delivery must not leave copied application sources in authored paths. Release evidence must identify container versus Edge execution honestly.
