## Problem and decision

Local Community browser/API tests depend on disposable accounts and database setup. The hosted learning adapter has an academic closed command catalogue and cannot certify community posting, moderation or revocation by changing its URL. A second copy of its filesystem journal or product mutation logic would create competing owners.

Extract one durable local command journal into `scripts/verification/hosted-command-journal.ts`, with contracts selected only by the source-owned learning-loop/community discriminator. Thin wrappers retain separate purposes, roots and operation types. The learning wrapper preserves its public interface, original version-one owner/record/head bytes and all existing tests. Journal metadata does not confer native or provider authority; runner-loss recovery still requires externally trusted original manifest/head evidence.

The finite community parser uses existing shared request contracts and the existing public Community receipt validator. It pins the fictional School001/class001 teacher004/student012/peer018/parent072 tuple and limits actions to newly observed test-owned group/posts/announcement. Its operation aliases explicitly distinguish normal `report.create` from journal `post.report`, and maintenance group/withdraw from normal community commands. Raw request digest and normalized native fingerprint remain separate. Receipt IDs may identify a change or revision rather than the original object; native evidence must use the exact current SQL mappings.

The forwarding gate journals the original command before its one callback and rechecks current external admission after local durability preparation. Unknown outcomes retain their original key, body hash, source and object identity. Supplied callbacks and local HTTP confirmation do not certify official admission, native persistence, worker processing or customer acceptance.

One visible Community journey reuses the existing one-POST observer, navigation and receipt validation. Exact actor/class/source choices replace first-role or name-prefix assumptions. Local setup, evidence directories and held-response fault injection remain local. Hosted use supplies the finite fictional recipe text and needs its own confined Auth/API/private-channel admission; it cannot reuse an academic blanket WebSocket policy or enable external messaging.
