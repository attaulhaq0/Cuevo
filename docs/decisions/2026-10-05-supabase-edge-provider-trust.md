# Supabase Edge and Cron provider trust boundary

Status: founder-approved implementation direction on 5 October 2026. The selected runner remains the existing signed Supabase Edge worker with one-minute Cron recovery. Source implementation and local/hosted acceptance are separate; this decision activates no key, dispatch, schedule or hosted release.

Keep the durable outbox, existing source-authorized processor, current HMAC envelope, restricted worker login and generation/event leases. Replace only `internal.worker_transport_private()` through append-only migration `20261005132902_worker_transport_provider_trust_boundary.sql`. The prior stricter migrations remain immutable historical evidence. There is no approval table, daily renewal, catalogue ledger, second processor or per-school policy.

Supabase provider/control-plane SQL owners and the server-only Storage credential holder are explicitly trusted. `service_role` may retain managed Vault/net grants under this policy, but gains no Cuevo signed delivery, configuration, raw control/outbox or private domain RPC permission. A full API compromise may expose that Storage credential and a trusted provider/control-plane compromise may access Vault. These are accepted residual risks, not a claim that the service credential is harmless or that SQL defeats provider authority.

The per-activation/per-send predicate inspects current metadata, never secret values or queue rows. It requires known roles, schemas, sensitive relation kinds and trusted object owners; denies PUBLIC and untrusted table, column and sequence privileges; and checks every current or future Vault/net routine using schema USAGE plus effective EXECUTE. Default PUBLIC execution behind an unreachable schema is insufficient for a callable path. Untrusted role membership is followed conservatively through every inheritance/SET edge, including dormant edges. Privileged role attributes, administrative membership, schema CREATE and object ownership refuse dispatch. Provider indexes and composite types are not tables and do not falsely invalidate a safe catalogue.

PUBLIC, anonymous, authenticated and service-role execution of app/internal/authorization functions remains denied, except the exact separately source-reviewed `authorization.community_realtime_topic(text)` for authenticated private Realtime. Its owner, boolean return, stable definer and fixed empty search path are checked. This shape check does not prove every function's semantics: current SQL source review, authorization tests and the prohibition on arbitrary SQL/RPC/endpoint bridges remain mandatory. Cuevo API/worker capabilities retain their existing fixed purpose grants, and neither may call the transport guard, sender, configurator or wake requester directly.

Hosted Data API **disabled** is a release and activation prerequisite for this selected configuration. SQL cannot truthfully attest an external dashboard setting continuously. Before provisioning a reusable signing key or activating Edge/Cron, obtain current exact-project configuration evidence and anonymous/authenticated/service-key negative REST/GraphQL/RPC tests, plus functional Auth, private Storage and protected Realtime proof. Provider upgrades or exposure/grant/function changes require pause and current revalidation. Unknown or re-enabled exposure prevents hosted activation; a catalog predicate pass alone cannot certify it.

The ordinary local bootstrap may retain its existing stricter provider hardening. A separate required local provider fixture follows the ordinary SQL suite: exact Cuevo project/56321/56322/container, real `supabase_admin` session, PostgreSQL17 and one rollback-only synthetic fixture. It uses no secret or network invocation, emits only a passing TAP count and fails on incomplete evidence. It grants no runtime privilege and cannot target hosted or the independently owned scratch stack. Root-owned scratch proof may use the same fixture only under its separately authorized target validation.

Validation requires actual service-provider positive metadata, each untrusted/PUBLIC relation/column/sequence/callable routine denial, private RPC refusal, role/ownership/CREATE drift, exact Realtime preservation, current signed sender and activation false-guard behavior, real restricted-login/source/lease/idempotency recovery and unchanged native values. This implementation's source/fixture checks do not establish hosted deployment, total handler deadline, concurrency/fairness, representative load or MVP/customer acceptance. The [scalable execution foundation](../architecture/scalable-event-processing.md) and original [worker decision](2026-10-02-event-triggered-worker.md) still govern those boundaries.
