# One workspace navigation and source-state presentation

The founder requested consistent focused navigation and Cuevo styling for empty, failed and unassigned states across all five roles. Screenshots showed Progress's peer chapter rail below its heading and a Next steps empty view with repeated headings, plain text and a detached pagination message. The approved Trail/focused/content-first direction remains the design authority.

The shared UI package owns `WorkspaceNavigationContent`, a presentational portal to the existing host. `WorkspaceTabs` uses the same placement; Progress moves its live native chapter links and utilities through it. Native chapters retain current target/hash/focus behavior and do not become tab selection or Shell h1 activation. Feature queries, source admission, selected child, commands and callbacks stay with their existing owner. No DOM extraction, callback registry, second navigation router or copied reader is introduced.

`WorkspaceState` owns the common opaque reading material, existing icon, compact text/action anatomy and logical spacing. Empty/loading/unavailable/denied/unknown/review are caller-supplied meanings. Default titles are strong text; real h2/h3/h4 hierarchy is explicitly chosen by the owner. Actions and recovery remain current authorized callbacks. Shared errors retain their original alert, uncertain-request instructions and optional closed support reference; no automatic retry or permission rule changes. Terminal pagination reserves no extra row and makes no source-completion claim. Partial/failed continuation still exposes its actual control and error.

Existing feature empty/loading paragraphs adopt this anatomy with their same copy and predicates. Improvement removes repeated directory headings while keeping standalone headings and named keyboard destinations. Baseline query loading/error/incomplete states are no longer presented as confirmed empty. Development ledger/milestone explanations distinguish a selected learner's loading summary from absent selection or disabled recognition. Parent child loading, partial and failed reads remain distinct from no approved relationship. Current source and unknown values never become invented tasks, grades, mastery or XP.

Narrow Home reading insets use UI-owned physical caps while typography enlarges normally. The existing adult Home outer inset preserves16px; Parent nested insets preserve their normal12/16px values. This avoids repeated font-relative padding consuming the reading plane at320px. Focused editor padding and Student Home geometry are not altered by this Home-specific policy. Existing approved illustrations, Royal primary/Pearl selection/status semantics and Midnight backgrounds remain.

Unit/isolated owner passes remain separate from complete MVP/backend/hosted/customer acceptance.
