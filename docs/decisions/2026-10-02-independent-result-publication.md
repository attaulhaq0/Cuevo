# Parent publication is separate from native grade authority

Date: 2 October 2026. Owner: academic source/results with portfolio consumers.

An immutable native result retains the parent's approval state when that grade was released. Ongoing publication requires separate human access authority: an append-only result_publication_revisions ledger is keyed to the existing shared native result identity, preserving numeric/rubric IDs, criterion/score/policy, evidence and history. Without a publication revision, release-time approval supplies compatibility revision0. An absent source never defaults to published.

One result_parent_published helper resolves current approval for each exact release. Parent current lists/reports apply it before paging; every history row, native source/result/evidence/current pointer RLS and portfolio_source consult the same authority. Current tenant/role/guardian/person/course/programme/source authorization remains in front of the publication decision. Student/teacher access does not depend on parent sharing. Portfolio publication is additionally required and cannot override revoked academic source publication; held artifact delivery reauthorizes the shared source after private storage returns.

The purpose-specific publication command verifies current teacher/admin ownership, learner/programme/native source, expected publication/result revisions, human reason and confirmation before idempotent mutation. It uses a raw internal course lock independently of retired academic work availability, because publishing retained evidence does not reopen or change learner work. Every important access change has audit/outbox/receipt; no grade/evidence revision is added or altered. Explicit sharing of an originally private release is supported, while revocation affects only that exact release.

Native sources, reports/exports/history, selected portfolio source text/artifacts and private bytes require consistent denial after revocation. The server cannot erase a parent's previously downloaded file; UI does not imply that it can. Browser in-flight export/delivery uses fresh authorized reads and current access generation as well as server reauthorization. Root owns exact SQL/API/browser/storage verification and clean synthetic restoration.

Current-result pages/native current-source/state require active enrollment of the exact child in the source class. Retained grade/evidence history has a separate approved policy: a current authorized guardian may read currently published immutable evidence only when the exact child's historical enrollment covers the source submission time, the immutable submission/result/evidence/reference/version identity agrees, and current programme/source-rights authority remains. A sibling's enrollment cannot supply that historical scope. Revoking the guardian or publication denies retained and current reads; withdrawing current enrollment removes the result from current reports while leaving authorized historical evidence. This purpose split preserves SQL115's historical contract without weakening current-source authorization.
