# Portfolio page source and identity reuse

The production browser pilot fixture exposed a student portfolio timeout while loading its full supported 100-record page. Read-only profiling under the actual `cuevo_api` student role confirmed the unchanged five-second SQL limit: one item returned in 92 ms, 25 in 1,077 ms, and 100 timed out at 5,010 ms. The fixture contains 500 synthetic students and 101 independently selected released evidence items for the original reference learner. This is local synthetic evidence, not hosted capacity or a deployment latency promise.

Each list row already calls the canonical `portfolio_source` function to verify its exact source and current access. The subsequent `portfolio_record_identity` call repeated that source check before building the current learner/class/year/course/task/submission context. The exact source call took 15 ms and the full identity helper 40 ms. The candidate plan uses ordinary item/current-revision/review joins; repeated source and identity work, rather than a larger page payload, accounts for the measured page growth.

Applied migration `20261002235224` factors the existing identity body into private `identity_from_validated_source(jsonb)`. Only the owner may invoke it. The list supplies its immediately authorized source object; the canonical identity wrapper still calls `portfolio_source` before the private helper, preserving command and replay authorization. The helper retains the exact submitted context snapshots, current human names and authorized same-class duplicate-name check. There is no persistent cache, raw runtime grant, changed model rule or smaller page limit. Parent revision pointers, source publication, review metadata, artifact counts, denied-row continuation and immutable historical evidence retain their existing functions and row behavior.

The source remains current at its canonical authorization point. A later mutation/replay repeats its own checks; returned page data is never used as permission. Independent full-page parity, role/tenant/parent/revocation/duplicate-name tests and repeated 100-record timing remain required before this repair can be claimed verified. The initial read-only failure is retained in `.local/performance-investigation/portfolio-profile.json`. Applied bytes are immutable: 5,208 LF bytes, SHA256 `253df3bf1cc8c66a98d5eb05a8e792d77f9164528b568f475d9894fbf1579421`.

Five student and five parent full-page reads after the first factorization all still timed out at the unchanged five-second SQL limit. This disproved the narrow repair as sufficient.
