# Foundation decisions

The founder's direct instruction makes E Deviser the company and Cuevo the product. Numbered specifications remain historical source records; implementation and runtime documentation use the corrected naming.

Use npm workspaces, one package manager, Node 24 LTS in Docker and pinned dependencies. Local Node 26 is available but reproducibility targets 24. A different npm/workspace runner can be considered only with evidence.

Use the population in specification 77 (60 students, 8 teachers, 6 classes, 8 subjects) because it is the later, explicit synthetic-school requirement. Specification 41's smaller earlier seed is retained as a conflicting historical example. No synthetic archetype is a psychological label or authoritative academic claim.

Use lowercase improved/no_meaningful_change/inconclusive/unmeasured for eventual outcome commands, preserving baseline and comparability. The attached goal takes precedence over older uppercase synonyms; unmeasured never means unchanged.

Approval/visual-selection gates in Superpowers/Product Design are superseded by the founder's explicit unattended instruction. Existing configured credentials may be used; absent credentials are blockers and no new key is created without a separate explicit request.

Committed migrations remain the database source of truth, including local iterations, overriding the Supabase skill's ad-hoc SQL/diff workflow. Cuevo ports 5632x preserve existing Edeviser-Kiro services at 5432x.
