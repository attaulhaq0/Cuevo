# Fresh admission for pending original worker confirmation

Status: bounded source design approved 8 October 2026; source implementation and controlled verification are in progress. No hosted execution, provider change or customer acceptance is recorded here.

The original activation may complete signed source and scheduled recovery with released operator/Auth cleanup, then fail final confirmation or lose its COMMIT acknowledgement. Its completed failed workflow cannot satisfy the live original release admission. A same-live-only CLI would therefore strand the intended recovery.

Choose a distinct `pending-runtime-confirmation` package scope. It requires the exact original source/tree, a fresh canonical CI/current run/package/founder approval and independently admitted immutable original execution export. Preparation reads only credential-free original evidence and public CONFIGURED/exact CONFIRMED candidate metadata, complete installed migration/history/population/Auth/private posture and original dispatch/Cron. It builds the existing verified zero-pending runtime-only plan and inert source artifacts; this scope cannot migrate, provision, deploy, reactivate, wake, pause or run downstream effects.

The original producer retains its exact public identity before effects and exports only the strict original intent/identity/execution/cleanup, frozen successful EXECUTION_FINAL prefix and key/configuration hashes. Public JSON is capped at256KiB, archive2MiB, prefix64KiB/64lines and whole local journal1MiB. Raw file hashes and canonical receipt hashes remain separate. Private keys/configuration/provider response bytes never enter the export. An exact existing export retains its original clock; conflicts refuse. The fixed hidden-file upload has its own successful producer/upload steps even if original activation failed.

The official historical artifact owner accepts terminal success/failure only with exact source/run/attempt, original founder approval valid at execution and cleanup, successful original approval/export/upload steps, bounded one-member canonical archive, current nonexpired artifact and stable repeated metadata. That evidence grants no native permit or current approval. Missing legacy original evidence remains review.

The shared native confirmation owner has separate initial and pending entry points. Pending recovers original private runtime only inside verified operator TLS and the original advisory lease, checks independent key/configuration/identity/export bindings, rechecks actual current source/history/population/private/key/Cron/control before and after one CONFIGURED→CONFIRMED CAS, or observes exact CONFIRMED with zero saves. Commitment, lock release and socket closure remain separate. No automatic retry/new key/source/wake/provider/dispatch operation occurs on uncertainty. Current reconciliation result keeps current and original identities distinct; failed original terminal files and clocks remain immutable.

After successful pending run B, ordinary installed-runtime run C separately prepares and approves genuine CONFIRMED metadata and executes existing current verification/recovery/restore/API/handover/web phases. B cannot silently change its approved scope into C's capabilities. Initial direct consumers retain official successful activation-step plus observation-only native proof, so partial local success publication cannot independently authorize them.
