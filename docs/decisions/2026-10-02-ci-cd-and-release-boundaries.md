# CI/CD and release trust boundaries

Status: implemented foundation; hosted execution, backend hosting and deployment acceptance require separate evidence. Date: 2 October 2026. Sources: product02/39/68/78/81/82/83 and the repository constitution.

Cuevo keeps Next.js web on Vercel, the existing NestJS/Fastify modular API on a reviewed HTTP runtime and separate Supabase environments. The [accepted event-triggered worker decision](2026-10-02-event-triggered-worker.md) supersedes this decision's earlier persistent-worker-host requirement: the working local candidate uses bounded signed Supabase Edge wakes and the existing private SQL processor, with hosted permissions/credentials/recovery acceptance still required. Domain behavior stays with its existing owner; database migration and academic/source authority remain private and append-only.

Untrusted pushes/PRs execute structural, documentation, unit, security and the full frozen synthetic verification. No deployed/provider/database secret is passed into these jobs. A single exclusive technical job retains the clean-bootstrap/API/SQL/outage/recovery/browser sequence, installs all three required engines and allows 90 minutes. The required status depends on fast checks, the technical job, PR dependency review and CodeQL. Runtime dependency audit, source/grant denial and restored-security tests remain required alongside code scanning.

Actions are pinned to GitHub API-verified commit SHAs. Checkout credentials do not persist. Default permissions are read-only; CodeQL alone receives security-events write. Dependabot proposes reviewed updates. CODEOWNERS identifies the existing repository owner for sensitive boundaries; GitHub rules must require that review, dismiss stale approvals and require signed commits. An AI agent's proposal or review is not independent human approval.

Manual web release is restricted to the exact main commit with successful canonical push CI. Protected staging/production environments supply strict release manifest version1: the API retains its container commit/origin/image/health identity, and the worker requires an explicit `kind` for container or Supabase Edge execution. Containers retain image/origin/health fields; Edge requires matching Supabase project, `cuevo-worker` function, source artifact/Deno lock hashes and true authentication/queue-recovery/role-grant/transport-privacy proofs. Matching migration versions/hashes, grants/RLS/private Storage/private Realtime/recovery and the correct human environment approval remain mandatory. Seventeen contract/actual CLI cases pass. The saved original manifest is re-admitted within24hours at verification; its timestamps, hashes and proof fields are reviewed operator attestations, not cryptographic signatures or regulatory acceptance. Missing hosting or evidence stops release. Production remains subject to school/provider/residency/contracts approval.

Vercel builds consume only the reviewed public web configuration; backend/provider credentials are excluded. GitHub staging maps to the standard Vercel Preview target, so the foundation does not assume paid custom environments. The pinned CLI accepts the token through its environment rather than argv. The script hashes and scans the prebuilt output before upload and verifies raw team-scoped deployment metadata for project/team/SHA/target/URL plus web/API readiness and container-worker `/health/ready` when applicable. Edge verification consumes the re-admitted operator evidence and sends no GET or signed POST to the worker; it establishes no fresh Edge network or source identity. Container image and Edge artifact/lock identity remain reviewed external evidence. Production uploads use `--skip-domain`: domain promotion requires the subsequent staged role/security/signature/lease/recovery/critical-flow review. API/worker deployment and remote migration targets still require reviewed immutable artifact deployment and rollback commands before complete platform CD; the hosted pipeline foundation remains pending actual acceptance.

Only sanitized CI identity, step status/timing and source file counts are uploaded. Raw logs, browser traces/screenshots, Auth accounts, private Storage bytes, backups, credentials and broad `.local` archives are excluded. Full sensitive diagnostics remain restricted on the ephemeral runner. A fail-closed JSON validator rejects unexpected release fields and inconsistent dependencies.
