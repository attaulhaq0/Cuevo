# Native academic source identity for improvement

Status: implementation in progress. Authority: source pack FINAL-2026-10-01 IDs10/12/17/38/39/83. This decision does not define official curriculum, level ordering or a rubric improvement rule.

Numeric and rubric releases currently retain separate immutable native tables. Improvement’s source foreign keys and numeric comparison commands point directly at numeric result revisions. A model-neutral result identity is required before rubric evidence can use the same proposal, approval, task, help and reassessment ownership. Duplicating the full improvement subsystem for rubric evidence would create competing command/history implementations; converting descriptors to numbers would discard native truth.

Add a private academic-owned result-source identity whose ID equals the original immutable numeric or rubric result ID. Each row references exactly one native revision through explicit model/learner/source foreign keys; immutable triggers populate it during native release, and existing revisions are registered transactionally. Native result tables remain the source of truth, their routes/IDs/history unchanged. Current read/command authority resolves the native source through one purpose-limited private boundary that validates current role, learner/course/programme, reference/evidence and latest submission/result.

Improvement will reference this identity for source links and consume a strict native descriptor through its existing actor transaction; no application imports another application or academic runtime implementation. Browser-safe contracts distinguish native numeric values from exact rubric criterion descriptors. Numeric commands retain their current scale checks and measured outcome policy. Rubric proposals preserve exact criterion keys/levels/descriptions with bounded checked citations and teacher-review limitations. They never normalize levels or infer higher attainment from names/order.

Rubric reassessment may retain exact compatible before/after descriptors with comparability UNKNOWN. A later explicit versioned school comparison policy is required to classify improved/no-meaningful-change; absent policy cannot become zero or false. Shared task completion and approval stay deterministic, auditable/idempotent/outbox-backed and currently source-authorized.

Migration history remains append-only. Acceptance requires old numeric source/deny/replay journeys, native bridge identity/immutability/grants, rubric current/foreign/stale-source denial, exact native provider context/output, human approval/tasks and descriptor-only reassessment evidence. Source registration alone is a prerequisite, not a completed rubric intelligence workflow.

The next owner increment supplies private read-only native result/evidence/current views with the same immutable source identities; rubric score/maximum columns are null and never exposed as a native score. Only improvement baseline foreign keys move to the identity bridge. Existing source/approval/task functions consume that shared projection through asserted changes. Scalar numeric outcome source constraints remain intact until descriptor-only outcomes are implemented. This permits a teacher-authored rubric task through the existing domain without duplicating rubric recommendation/intervention tables.
