# Installed runtime evidence lifetime and contract observation

Status: bounded source implementation; protected integration, actual hosted updates and rollback remain unverified.

Ordinary forward preparation previously required the old runtime ZIP and all original source proof artifacts. Source artifacts retained fourteen days while runtime artifacts retained ninety. A healthy older installation could therefore fail its next update even though the desired release had new verified artifacts. Rollback also required a two-day frontend handover artifact to recover historical API and Edge IDs.

The existing native current generation already records source/tree, provider IDs, API/Edge/Deno-lock hashes, the migration-set hash, its original operation and package, and a confirmed state digest. Ordinary no-schema-change forward preparation now uses that positively observed current state and exact historical Git contracts. It verifies the old migration list against the installed generation hash, compares the unchanged runtime contracts, and consumes only the new source's verified CI artifacts. No old ZIP is downloaded or copied and no old artifact provenance is invented. Missing historical Git objects, changed contract authority or pending migrations still require review. Current source CI, target checks, the fresh exact founder package and native lease/source/provider checks remain mandatory.

Historical contract observation has one explicit function in `runtime-contract-manifest.ts`. It reconstructs the selected original source/tree from bounded immutable Git blobs and historical migration bytes while preserving the current checkout metadata. The ordinary current-source reader still requires matching HEAD and current physical SQL. Historical observation provides contract facts; it never authorizes an old release, executes old code or renews an expired approval.

Rollback still requires actual retained original binary and contract receipt bytes within the configured ninety-day artifact window. Preparation derives only a historical provider-ID candidate from the existing private provider receipt owner: one exact confirmed operation must match source/tree, API/Edge/Deno-lock hashes, target and previous generation. It repeats that observation before publishing the package. The old frontend handover is no longer required to select those IDs.

The candidate is not verified native history. The existing rollout session reads and authenticates the encrypted history chain and compares the exact prior generation, source, artifact hashes and API/Edge IDs before any pause, upload or alias effect. A wrong candidate ID can appear in a reviewed preparation package but cannot pass that native boundary. Local tests exercise that distinction: a wrong deployment ID and changed encrypted history bytes leave state unchanged and cause zero provider, alias or history-write effects. Changed target/provider hashes or a changed final provider read prevent preparation publication.

Current source, runtime lane and delivery evidence retention is aligned to ninety days by their workflow owners. Original expiry fields remain immutable. Expired or missing rollback bytes are not reconstructed from provider version labels or ignored. Outside that window, deploy a newly verified forward fix under fresh approval; arbitrary historical binary rollback is unsupported. A source-only or hosted operating receipt never establishes customer acceptance.

The enclosing canonical readers also reuse one small captured checkout metadata guard after their final awaited observations. This checks actual root, HEAD/tree, replacement/graft absence and clean source without replaying the immutable blob inventory. Captured closures remain process-local and are not serialized as passing proof.

These changes reduce repeated artifact reads and copies while preserving original state and approval boundaries. They do not establish the whole-CI fifteen-to-twenty-minute target. The existing provider owner has a twenty-operation bound and encrypted history traversal has a one-hundred-generation bound; a verified archival/rotation policy for longer operation is not implemented. Pending schema/interface maintenance and full customer handover with retained older components remain separately unsupported. Do not call the complete future release lifecycle or hosted application finished from these local tests.
