# Fixed source fixture CI partition ownership

Status: bounded implementation for source critical-path optimization; exact candidate CI and measured whole-CI timing remain unverified.

The single source job previously executed every original fixture group, with CICD and migration groups already overlapping. New runners must avoid a second execution path and preserve complete discovery. `ci-partitions.json` assigns each original source test file to one of three reviewed whole-file producers. The existing `stateless-checks.ts` owner accepts a closed partition argument and launches the original Node process-isolated test path with existing default file concurrency. It records original source/tree/physical digest, lock/toolchain/Node/environment policy/run/attempt/job and actual parent process result with before/after source confirmation. Original fixture definitions and assertions remain unchanged.

The safe reporter observes actual Node lifecycle, case/definition identities and per-file results. The collector checks top-level totals as the sum of independently validated per-file declaration counts; Node's global value is not the number of files. Its scheduling dequeue hint may identify a nested test as a suite, so the original enqueue definition and checked completion/terminal types/counts retain unit authority. Actual one/multiple-file Node regressions preserve complete nested/duplicate/missing/skip/TODO/error/clock outcomes. Node `.only` is not enabled by this closed invocation, so it executes all required declarations; no filtered invocation or new authoring policy is added.

The signed partition manifest also declares exact ordered non-test source check names and command hashes. The current coverage guard compares those declarations to its compiled source steps before every producer/aggregate. Historical metadata can therefore validate the original signed table and archived outcomes using the known same guard/runner bytes without executing historical code or pinning every evolving test argument in the whole steps file. Missing, extra or changed declarations refuse; this declarative table creates no separate effect authority.

`stateless-source-aggregate.ts` consumes exactly one canonical minimized result per fixed producer, validates source/job/run/attempt/manifest/file/case union, checks its own physical source hashes and source freeze, and runs original non-test source checks once. Unsafe input/output paths, missing/extra/noncanonical/changed input or any unconfirmed producer prevents completion. Each producer and aggregate uses its own hosted runner/scratch. Failure/cancellation keeps fixed safe incomplete metadata; no raw logs, SQL, titles, credentials or arbitrary errors enter retained JSON.

`verification-workflows.ts` retains `source-contracts` as the required status aggregate and pins all three producer jobs, exact artifacts and setup. The existing `required` status still requires source completion. Original same-attempt producer/aggregate GitHub artifacts, digests/bytes/clocks and complete source identity are consumed by `canonical-source-jobs.ts` and both canonical release readers; a self-hashed local receipt alone cannot authorize release. Existing one-JSON archive bounds of 1 MiB JSON/2 MiB archive remain.

Database setup/authorization, CodeQL, secrets, integrated-main staging, full regression/customer-candidate acceptance and founder/hosted authorization remain separate. Source partitions have unknown per-file costs until actual managed timings; extra runners do not prove a 15–20-minute pipeline. Backend/API isolation and browser scope are unchanged by this source increment. Original complete local/stateless paths remain available without becoming fallback CI admission.
