# Personal repository release-control readback

Status: implementation correction within the founder-approved independent-agent/founder release policy. No artifact, merge, deployment or provider activation is approved by this decision.

GitHub's current protected-branch documentation states: “Actors may only be added to bypass lists when the repository belongs to an organization.” Cuevo is currently a public User-owned repository. A live protection update containing empty user/team/app bypass allowances was rejected with422; the supported personal-repository update succeeds without that field, and current readback omits it. Omission alone cannot establish safe configuration for an unknown repository.

The existing release control reader now also reads exact current repository metadata from the same official GitHub API during every existing control revalidation. The repository full name, name and owner login must match the expected repository, and a positive owner identity with a known User/Organization type is required. If an own bypass field exists, all three arrays must be explicitly present and empty. Null, undefined, malformed, accessor or nonempty data is refused. If the field is genuinely absent, only verified User ownership permits the distinct nonconfigurable personal-repository verdict. Organization or unknown ownership with missing metadata is refused. The adapter does not invent empty arrays, cache ownership or create a customer-specific branch.

Strict required CI, signed commits, enforced administrator protection, a present PR rule, stale-review dismissal, zero second-human review count, disabled CODEOWNER/last-push approval, no force push/deletion, exact founder environment review and disabled environment administrator bypass remain mandatory. Independent immutable source/QA reviews and exact-package founder approval still precede provider credentials. Ownership transfer, unavailable metadata or changed controls are rechecked and must fail before release.

Both environments have sole reviewer User95836629/attaulhaq0, deliberately permit that founder's self-review and deny administrator bypass. The latter setting was saved through GitHub's supported Settings UI and independently read back. Initial failed API requests are retained as provider capability evidence; they changed no protection. Actual settings are distinct from source-test acceptance, Actions-token read permissions and complete release readiness.
