## Event and diagnostic flow

Current intelligence metadata extends the same delivery path. Newly recorded terminal output observations and explicitly confirmed quality reviews each write a source event in their own existing transaction. A private projection validates immutable run/binding/source/current actor scope before capture. The worker converts run/context identities to HMAC references; no prompt/output/source arrays or review reasons are exported. Linked decision/support/outcome events carry the same run reference. Context counts remain nullable, output acceptance is structural, and usefulness/privacy/tool safety remain actual reviewed categories or UNKNOWN.

Cost charts aggregate only cuevo_intelligence_run_observed, since linked stages repeat run metadata. DETERMINISTIC_FIXTURE has zero external tokens/cost; CONFIGURED_TOKEN_RATES is an estimate; BUDGET_RESERVATION remains a reserved amount; LEGACY_UNSPECIFIED/failed unretained usage remain unknown. Billed cost stays UNKNOWN. Custom Cuevo events avoid PostHog native model-pricing assumptions being mistaken for a Foundry invoice. No new external model call was made.

```text
Authorized source command → source/audit/outbox transaction
→ restricted domain worker completes source event
→ environment-bound private delivery claim
→ current policy/all-synthetic/source/lease revalidation
→ minimized HTTPS capture
→ durable accepted/retry/failure receipt
→ PostHog indexed readback
```

Both Node and Edge use apps/worker/src/jobs/analytics/posthog-delivery.ts. The portable mapper is worker-owned; @cuevo/contracts/analytics is a narrow server-free names/types export. Remote receipts are separate from historical local fixture files. Uncertain POST or acknowledgment uses the same destination HMAC insert identity. An HTTP200 only confirms capture acceptance; query readback proves indexing. Five bounded attempts, durable delay and explicit failures preserve investigation. The configured pseudonym key must remain stable for its version; do not replace it during uncertain retries. Rotation needs a new version and preservation/reconciliation of old retry context.

Optional diagnostic fields are only category, feature, status, timing, locale and viewport enums. Browser uses authorized /v1/diagnostics/config and /browser through the API; it has no PostHog SDK.
