# Load product context for the task

The repository stores the complete product corpus. It does not automatically place every document into an AI model's context. Use progressive disclosure: read the common foundation once when unfamiliar, then the relevant source bundle for each work unit. Do not replace an authoritative curriculum/security fact with memory or a summary.

## Initial orientation

Read root AGENTS/README/START-HERE, [constitution](overview/00-PRODUCT-CONSTITUTION.md), [plain-English product](overview/54-WHOLE-APP-IN-PLAIN-ENGLISH.md), [MVP gates](overview/01-MVP-SCOPE-AND-GATES.md), [exit criteria](overview/83-MVP-EXIT-CRITERIA.md), [domain model](overview/03-DOMAIN-MODEL.md), [architecture](platform/02-SYSTEM-ARCHITECTURE.md), [stack ADR](platform/68-FINAL-TECH-STACK-AND-ADR.md) and [security](platform/39-SECURITY-PRIVACY-AND-AI-GOVERNANCE.md). Then read [build order](delivery/87-IMPLEMENTATION-ORDER-FINAL.md), [codebase map](../codebase-map.md) and [current status](../implementation-status.md).

## Every task

1. Read root entry instructions, the nearest scoped AGENTS and affected owner README; inspect Git changes and current gate/status.
2. Choose the bundle below. Load its relevant tests/golden cases and approved curriculum/version artifacts. Expand the bundle when a task crosses domains or affects security, data or UI.
3. Record the governing document IDs/versions and verification in the plan/handoff. Missing facts remain UNKNOWN/REQUIRES_REVIEW; no live academic guessing.
4. Follow source rules, public interfaces and current scope. Verify the change and update navigation/registry when paths or sources change.

## Find a source by its old filename

Use `rg --files docs/product`, the full [index](index.md) or [registry](registry.json). Narrow text search by task folder, for example `rg 'native result' docs/product/domains docs/product/curriculum`. Every numbered ID and old root filename maps to one current source. Use current paths in new plans/owner READMEs; do not create duplicate specs at old locations.

This guide governs context loading only. Product invariants, curriculum rights, approval boundaries and required verification are unchanged.
