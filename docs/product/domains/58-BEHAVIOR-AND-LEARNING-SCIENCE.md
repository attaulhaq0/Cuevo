# Behavior and Learning Science for Edeviser

## Purpose

Use established learning/behavior frameworks as design lenses, not as diagnostic or psychological scoring systems.

## Fogg Behavior Model

Official reference:
https://www.behaviormodel.org/

Fogg describes behavior as requiring Motivation, Ability and Prompt to converge.

Edeviser use:
- diagnose why a desired learning action did not occur
- make actions easier
- choose a helpful prompt
- avoid prompt spam
- design small learning actions

Example:

Target:
“Complete a 10-minute revision activity.”

Check:
- Motivation: is the learner interested/committed?
- Ability: is the task small and accessible?
- Prompt: did a useful cue arrive at the right time?

Do not:
- create a “motivation score”
- infer motivation from clicks
- claim FBM predicts a child’s behavior
- use the model for mental-health or personality conclusions

## Self-regulated learning / metacognition

Use as a second design lens.

Core experience:
Plan → Monitor → Reflect/Evaluate → Adapt.

This supports:
- planning
- monitoring
- reflection
- goal setting
- strategy selection
- reviewing whether a strategy worked

The EEF 2025 guidance recommends explicit support for planning, monitoring and evaluating learning and describes metacognition/self-regulation as a useful evidence-informed teaching approach:
https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/metacognition

## UDL

Use CAST UDL Guidelines 3.0 as an accessibility/pedagogy design lens:
https://udlguidelines.cast.org/

Design learning experiences with options for:
- engagement
- representation
- action/expression
- accessible materials
- multiple media
- graduated support

Do not turn UDL into learner labels.

## Retrieval / practice / feedback

Use evidence-informed learning practices where curriculum/teacher policy permits:
- retrieval practice
- spaced practice
- worked examples
- targeted scaffolding
- feedback
- deliberate practice

These are learning strategies, not learner personality models.

## Edeviser development model

Combine the lenses like this:

```text
Learning objective
 ↓
Desired behavior
 ↓
Fogg diagnosis
 ├─ Motivation
 ├─ Ability
 └─ Prompt
 ↓
Self-regulated learning
 ├─ Plan
 ├─ Monitor
 └─ Reflect
 ↓
Accessible learning experience
 └─ UDL options
 ↓
Evidence
 ↓
Learner State
```

## What must NOT happen

These models must not be used to:
- score personality
- diagnose a learner
- infer protected traits
- label motivation as a fixed characteristic
- rank children as “good/bad learners”
- replace teacher judgment

## Founder-authorized reviewed Bloom task focus

The 4 October extension uses the revised cognitive-process categories as reviewed metadata about a specific activity or assessment criterion. Read the [approved integration specification](../../superpowers/specs/2026-10-04-reviewed-thinking-focus-bloom.md), [implementation plan](../../superpowers/plans/2026-10-04-reviewed-thinking-focus-bloom.md) and [private versioned vocabulary](../../../apps/api/src/modules/curriculum/pedagogy/README.md). Current implementation and acceptance status must be checked separately.

Remember, Understand, Apply, Analyze, Evaluate and Create describe task demand; they do not define six mandatory learner levels. A teacher may record a primary and additional processes after reading the actual materials; a different current authorized Coordinator/Admin reviews the exact source. Classification never follows a verb alone, activity kind, completion receipt, score, XP or inferred ability. Missing mapping stays unclassified, and source edits require current review while historical task snapshots remain immutable.

No knowledge-dimension scoring, learner diagnosis, mastery percentage, category-based reward or automatic prerequisite lock is introduced. Official curriculum alignment and academic grade rules remain independently source-locked. Student wording describes the current action, with bilingual Cuevo-authored explanations and optional source provenance.
