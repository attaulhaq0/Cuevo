# Product source instructions

Inherit root AGENTS.md. This is the product specification corpus, not implementation reports.

- Use context-map.md for task bundles and index.md/registry.json for source IDs/paths. Never assume the model already has the complete product context.
- Preserve numbered identities, facts, versions, rights restrictions and UNKNOWN/REQUIRES_REVIEW statuses. Navigation edits do not authorize product or academic changes.
- Keep curriculum, jurisdiction and quality/accreditation independent. Approved machine-readable artifacts/snapshots are separate evidence from these dossiers.
- Authorized source changes must update registry paths/hash metadata and relevant links/context guidance together. Never create conflicting copies or invent official rules.
- The original manifest/full brief are historical source context. Current root instructions/context map supersede only locations, naming and repeated-reading procedure.
- Original manifest and earlier briefs have one home in history/. Never keep a competing copy beside active sources. Historical evidence does not alter curriculum facts, rights or acceptance status.
- Run npm run check:docs and architecture checks after moves. Valid links are not academic approval or product acceptance.
