## Agentic intelligence: what is implemented

Sources10/12/60/65/78 describe one Teacher Insight & Intervention workflow. The current API follows: verified teacher/admin and purpose → private source/policy reservation → bounded context → provider call → strict fact/citation/action validation → current reauthorization → persisted proposal → separate human approve/edit/reject → intervention → learner completion → compatible reassessment → measured outcome/state. This is an orchestrated workflow with a real consequence boundary, rather than a standalone chat screen.

The provider factory supports deterministic fixtures and the server-only Microsoft Foundry Responses adapter. The live synthetic protected loop passed with one pending-human proposal, explicit approval, completion,3/10→7/10 native follow-up and observed difference4. Two total calls used772 input/360 output tokens; actual billing is unknown. No pupil data or real-data provider approval was established. Schema, current-source revalidation, private grants, bounded time/tokens, no provider storage and no grade/access tools are meaningful strengths.

The present intelligence is deliberately much narrower than the broad wording in the specifications:

| Mechanism | Current code | Constructive assessment |
|---|---|---|
| Request/intent | `analyzeInputSchema` accepts one numeric baseline ID; service purpose is fixed NEXT_LEARNING_ACTION | Good minimum purpose boundary; no class-wide analysis, selected teacher constraints or rubric baseline analysis. Do not call it a general agent platform. |
| Context retrieval | Stored insight includes up to10 compatible results,20 recorded observations,10 previous interventions/outcomes and10 approved learning options | Current authorization and review provenance are strong. Having this stored context is not proof that the model reasons over it. |

Interpretation/rationale are fixed server text, so the current model does not produce an independently assessed educational synthesis. |

The smallest useful intelligence improvement is to pass a purpose-limited, non-PII structured summary of the already authorized recent numeric sources, observed actions and prior measured outcomes, alongside the allowed learning option context. Keep retrieved teaching text untrusted, factual claims/citations schema-validated and consequential action human-approved. Add contrasting cases where the same baseline has different history/previous outcomes and verify the proposal rationale/path responds appropriately. Rubric insight needs a native criterion-specific design; never convert it to a made-up number. Do not begin a free-running multi-agent system or expose arbitrary mutation tools to solve this gap.

## What is already implemented or deliberately bounded

Native numeric and rubric release/correction are real; source83 minimum does not require forcing every broader source17 grade model into this increment. Proposal approve/edit/reject, teacher-authored support, learner completion/reassessment and observed outcomes exist. Multi-question quiz recovery, current own returned-work context, exact attendance correction drafts and session response races were repaired and tested. Those should be retained, not rewritten.

Account/tenant provisioning, credential recovery and entitlement creation are currently authorized operator tasks. They are not self-service invitation features. Memory-only sessions are an explicit control. Term/year rollover, official transcript and AI narrative reporting are unsupported implemented workflows; the documents do not justify inventing an automatic promotion rule or relabeling every one as an explicit post-MVP exclusion.

England selected-subject, Qatar jurisdiction and Cambridge0580 are included MVP targets requiring exact approved source-locked artifacts, rights/applicability and academic acceptance. They are not removed from scope by this report. Complete programme/subject catalogues, full accreditation/quality workspaces, finance/HR/payroll/native apps, public minor social networking and autonomous grades/access changes have explicit exclusions. Real-pupil/provider/residency/legal/production backups/alerts require separate external acceptance.
