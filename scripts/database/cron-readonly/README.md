# Current Cron facts and recovery advice

This is the database scripts owner's read-only source integration. `collect-current-facts.sql` retains its independently reviewed bytes. The successor pure policy extends the frozen review with an explicit PostgreSQL17 owner-ACL contract: all eight privileges including MAINTAIN, postgres-only and no grant option. An absent contract retains only the historical seven-privilege supplied-review shape; current mapping requires the explicit eight-privilege contract and excluded-role MAINTAIN=false. The policy has no I/O. `current-facts.ts` maps the fixed SQL response into bounded current facts and passes only the needed private projection to that policy. It never rebuilds original intent, before-row, arm or run custody from today's rows.

`inspectCurrentCronRecovery` accepts already captured response text and separately supplied read metadata/original evidence. Its authentication label remains `SUPPLIED_UNVERIFIED`; hashes and caller flags do not authenticate a read. `readCurrentCronRecovery` is a separate callable source function for an independently authorized operator. It authenticates one fixed HTTPS Management request using the supplied private token and sends only the byte-pinned read-only SQL. There is no CLI or automatic invocation. It takes no endpoint, arbitrary SQL, job, setting or effect selector.

The fixed reader retains the actual earliest issue and response completion times and uses the actual final decision time after the final source check. The original 30-second HTTP deadline and 10-second SQL timeout remain. Response size is at most 2 MiB, inner facts at most 1 MiB, and invalid UTF-8/BOM, redirects, partial bodies, aborts and source drift fail closed. The SQL retains its read-only transaction, transaction-local response and rollback. A failed transport remains unknown and is never retried.

All decisions keep `nativeExecutionAuthorized`, `nativeAcceptance`, `authenticCustodyCreated` and `futureEffectAdmitted` false. Complete supplied facts can produce review advice only. Missing original facts have an explicit `missingFacts` list. Current scoped-row/probe/Cron absence remains a dated current observation; a stale read retains that observation while refusing fresh advice. Raw settings, commands, ACL strings, return messages, control records and credentials are excluded from the returned summary and logs. Policy restoration advice is private operator material and must not be published as customer telemetry.

The held native execution, original history, acknowledgements, schema-only source input and approval boundaries are unchanged. This source integration is neither native mechanics proof nor hosted activation, recovery, pilot or customer acceptance.

Run `npm run test:cron-readonly` for the 49 preserved policy cases and focused mapper/reader cases. All data in `.fixture.ts` are invented simulations; reader transport is intercepted locally. Tests have one normal `local-runtime`/`source-delivery` discovery owner. The historical local review artifacts remain immutable evidence. See the [integration decision](../../../docs/decisions/2026-10-15-cron-readonly-recovery-adapter.md).

The main4f0 successor uses conservative native readStartedAt for policy eligibility; later HTTP completion cannot close an earlier native capture. Original HTTP and native capture/completion clocks remain separate. Before any await the reader captures the token primitive and a private deep snapshot from validated own data descriptors, preventing later caller getters/mutations from replacing credentials or original evidence.
