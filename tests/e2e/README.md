# Browser journeys

These tests exercise rendered application workflows through real named controls. Authoritative mutations, grants, source scope and durable receipts remain API/database concerns; an exact test record ID verifies the selected human context and never replaces it.

`selectTrailPortfolioRecord` verifies the exact current reader's level-two title after its independent record identity and human choice checks. A same-named lower source-work heading cannot substitute for that title or make a valid reader ambiguous. The helper retains current page receipts, Parent approved-item selection, pending/source refusal, and duplicate or disabled choice checks; its fixture covers matching source headings and wrong or duplicate primary titles.

`learning-lifecycle-diagnostics.ts` records only bounded response statuses/schema and exact-source parity booleans plus current DOM counts around the existing Return revalidation assertions. Queue schema status covers only the diagnostic's scalar ID/revision/status/page fields; exact source-work validation uses the shared contract. This is neither the application submission parser nor an authorization verdict. A failure emits one strictly validated fixed-code summary and rethrows the original assertion. Response bodies, identities, names, learner work, credentials and raw errors are excluded; missing observations remain null. It adds no request, interception, retry, timeout or production behavior.

The Return observer starts before the existing selected-submission click and retains bounded response history into the blank-editor revalidation. Arrival order determines the first observed HTTP/schema failure even when body parsing finishes later; twenty observations per category cap retained body reads and expose truncation. Unobserved bodies remain nullable. The editor's initial form/feedback counts are sampled once after the existing Return click with no assertion or retry; the original revalidation and editor assertions keep their original limits. Typed-editor revalidation uses a separate history window. This diagnostic never exports the application editor intent or adds a production hook.

`human-choice.ts` selects one enabled visible label, requires a nonempty bounded caption/value and checks an independently known receipt identity when available. `humanContextLabel` accepts one literal source title with a visibly separated bounded context suffix. Tests keep their own literal expected product words rather than importing product formatters to manufacture the oracle. Load additional choices only through the current authorized source's paging control before calling this helper; never resolve ambiguity by taking the first matching option or appending a database key.

Cross-application browser journeys stay here. Feature/parser/unit tests remain beside their owners; API/database journeys live in `apps/api/test/integration`, and SQL/RLS cases live in `supabase/tests`. Current English/Arabic, keyboard, mobile, hydration, source denial and axe assertions must survive presentation repairs. Generated screenshots/results and disposable records remain local evidence; restore the guarded synthetic environment after mutation journeys. Test capture does not establish official curriculum or production acceptance.

`trail-workspace.ts` owns test navigation for the single Trail chrome. `expectTrailWorkspace` requires the rendered school/person/current role, exactly one current rail destination and named primary main heading before continuing. Profile destinations and sign-out open the visible profile popover; sign-out waits for the bilingual sign-in form and disappearance of protected chrome. School directory helpers select one enabled human context before editing, preserving independent payload/receipt identity checks in journeys. Date selection uses the staff UTC input or current parent calendar controls. The helper imports no product dictionary, formatter, app implementation or fixture account, and makes no API/provider call. Browser discovery retains every existing test; source inspection/helper tests do not certify the integrated runtime.

Account, access and sign-out navigation first bring the real profile trigger into view and allow its document scroll to finish before opening the native popover. This models a visible user action and avoids the scroll-dismiss race after deep task work; no forced click or increased timeout is used. The helper regression uses an offscreen header and actual native popover that closes on document scroll, then verifies account-access navigation, the normal signed-out form and removal of protected chrome.

Focused destination navigation opens the current native chooser when it is closed, including after Home replaces its former popover node. The helper regression covers a closed replacement with retained expanded state. Customer label traversal returns to Home before checking the complete Arabic rail, then verifies actual content headings and the same feature's focused section controls or sole static subsection. Exact parent relationship restoration retains both the original verification failure and any restoration failure.

`result-reader.ts` adapts explicit Academic directory selection using an independently known current receipt ID and a nonempty human label. It loads only that current workspace's authorized result/reference/rubric continuation and preserves existing direct result routes. Tests still assert native values, source/evidence/history, current-child and publication denial. The helper changes interaction steps, never authorization or the expected receipt.

`selectTrailPortfolioRecord` opens one explicit current summary using the independently known receipt ID and its human title, following only the Portfolio item's own continuation. Parent selection requires a uniquely named approved directory record and verifies its exact approved receipt identity after opening. Missing, duplicate or disabled choices fail rather than selecting another record. Multi-item checks keep both summaries and inspect one reader at a time; denial checks retain summary and detail absence. Volume observations count directory summaries separately from explicit source reading. `portfolio-record-helper.spec.ts` verifies paging, exact selection, replacement, ambiguity and Parent identity without domain writes.

Navigation helpers wait for the current source page to commit before another continuation. School excludes transient empty loading DOM from page advancement; Portfolio verifies the actual GET page's summary identities or Parent row growth and terminal continuation, rather than treating a still-present More button as proof. `navigation-helper-settlement.spec.ts` preserves delayed-commit regressions. Pilot source selection uses the setup receipt's exact `lastPortfolioId` and recorded Portfolio entries, with the authored title checked through `pilot-portfolio-source.ts`; DOM ordering never chooses the source.
