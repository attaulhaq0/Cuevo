# Cuevo worker

`internal.outbox_event_owner(text)` selects one fixed executor by event type. Exact School account provisioning/recovery events belong to the API Auth executor; generic claim, lease exhaustion, complete/fail, source processing and due/wake recovery refuse them. Worker health and queue telemetry explicitly describe `WORKER` scope. The renamed prior source processor is owner-only, and every existing nonreserved event retains its original validation/review behavior. PostHog destination due-work remains independently eligible. This ownership repair supplies no Auth credential, sender or admission authority; genuine onboarding acceptance is still pending. [Admission/effect decision](../../docs/decisions/2026-10-03-school-account-admission-and-effects.md).

Hosted synthetic staging is an explicit exact project mode. Edge requires both CUEVO_DEPLOYMENT_ENVIRONMENT and CUEVO_WORKER_EXECUTION_MODE to equal synthetic-staging, with the configured CUEVO_SYNTHETIC_PROJECT_REF, exact HTTPS SUPABASE_URL and reviewed CUEVO_SYNTHETIC_WEB_ORIGIN. Direct database or pooler role must bind that same project; Node and Edge use TLS certificate verification. The portable @cuevo/config/synthetic-runtime surface owns these checks. Hosted analytics additionally requires STAGING; the existing private activation/current policy/population/source/lease checks and destination ledger still govern every send. An environment label does not activate capture. All ordinary tests keep capture disabled or use local injected transports.

The Node worker also requires verified SQL TLS in every production configuration, independently of whether NODE_ENV or CUEVO_DEPLOYMENT_ENVIRONMENT declares production. Its pool receives the validated databaseTls flag and refuses URL options that could override certificate verification. Local Node behavior and the explicitly guarded local Edge plaintext path remain unchanged.

Current minimized PostHog delivery is jobs/analytics/posthog-delivery.ts with worker platform/posthog.ts and a portable contracts/analytics names/types boundary. Environment-bound claims preserve source/policy/lease/cutoff/attempt control and separate remote versus fixture receipts. The Edge adapter keeps deterministic20seconds and configured shared30seconds work after admission: max1capture when domain work was attempted, max10analytics-only. A fixed failurePhase enum supports machine investigation; no raw errors or credentials are emitted. Intelligence terminal/review projections carry HMAC run/context references, explicit mode and nullable usage, estimate/reservation/unknown billing. Linked stages repeat metadata, so cost aggregates must filter terminal events. See [operations](../../docs/operations/posthog.md) and the [privacy ADR](../../docs/decisions/2026-10-02-posthog-current-repository.md).

main.ts composes scheduling and health. jobs/outbox/processor.ts processes claimed IDs/leases through private database functions; platform/database.ts supplies the worker pool. Source/projection/lease authority lives in supabase/migrations. The worker has no raw school/academic table grants and must never execute authoritative grades or model-proposed permissions.

Run root build for @cuevo/worker, test, typecheck/lint, database golden checks and relevant API integration. Test fixtures live in test. Unknown events remain bounded review/failure cases; explicit known acknowledgments are not proof of new state projections.

`platform/analytics-path.ts` anchors explicitly enabled synthetic fixture analytics to root ignored `.local/analytics`, independent of npm workspace working directory. Fixture analytics is forbidden in production. Normal worker configuration validates only its restricted worker credential; root process launch excludes API, Storage and model secrets. Live analytics delivery remains a separate integration prerequisite.

`jobs/analytics/posthog-delivery.ts` consumes completed, source-validated events through the separate private PostHog receipt. `platform/posthog.ts` maps only approved source types and exact browser diagnostic enums using portable WebCrypto HMAC; `platform/posthog-http.ts` posts to the fixed project ingestion origin with a three-second deadline. `LIVE_SYNTHETIC` requires explicit QA/DEMO/STAGING configuration, persistent key/version and a fresh database activation of an entirely synthetic populated school after current administrator analytics approval. Production and unapproved/mixed populations remain denied. Fixture receipts cannot count as live acceptance. Unknown capture/receipt keeps stable destination identity and bounded retry; confirmed in-flight acceptance remains recorded if policy is revoked after sending.

Node and Edge use the same live job. Edge retains the deterministic processor's20-second deadline and shares a30-second work deadline after admission with single30-second analytics leases, at most10 analytics events and23-second reserve per claim. Setup, finish and cleanup remain outside that work timer; it is not a total HTTP bound. Confirmed analytics acceptance contributes to wake progress so recovery can continue after domain drain. Disabled mode performs no analytics SQL or remote calls. The exact portable `@cuevo/contracts/analytics` source is admitted by Edge packaging; all other package/runtime boundaries and pinned `pg` remain unchanged. Local fixture/transport tests and actual destination readback establish different evidence.

`jobs/outbox/edge-handler.ts` owns bounded machine wake transport beside the existing processor. `src/edge.ts` is the minimal Deno bootstrap and platform/edge-database.ts owns the configured restricted TLS connection. POST accepts only a512-byte `{version:1,wakeId}` envelope with a3-second body-read limit. Before opening a connection, WebCrypto verifies the lowercase64-hex HMAC-SHA256 in `X-Cuevo-Wake-Signature` over `cuevo.worker.wake.v1`, the canonical epoch-seconds `X-Cuevo-Wake-Time`, and the exact wake ID, separated by newlines. The signing key is the configured64-hex secret as UTF-8 text and the timestamp must be within60seconds. The reusable key never travels in an HTTP header. Actual worker health precedes private begin_worker_wake admission; single-event claims have a20-second processing deadline/max10, then finish_worker_wake records COMPLETED/REQUIRES_REVIEW/FAILURE_RECEIPT_UNKNOWN and the connection closes. This processing deadline does not bound the entire HTTP invocation, which also includes connection, health, admission, finish and cleanup. False/unknown finish receipts are unavailable; inactive/duplicate wake returns202 without processing. No tenant/event payload/model/raw table authority is accepted.

The bounded processor reserves15seconds before each claim for existing5second claim/process/failure budgets and30second event leases; Node tick defaults remain10. The separate SQL invocation lease lasts60seconds from issuance and is not extended by admission. Queries preserve separate commits. Delivery pins pg8.23.1 and a captured Deno2.1.4 lock whose14-package versions/integrities match the root npm graph. The generated artifact carries frozen lock configuration; actual frozen Deno cache validation passed, while hosted bundler refusal of altered dependencies still requires a negative test. Production TLS rejects untrusted certificates; local plaintext is limited to explicit local-synthetic mode and the exact local database/container target. Pure tests do not establish DB/deployment acceptance. See [scalable event processing](../../docs/architecture/scalable-event-processing.md); SQL/packaging/runtime stays root coordinated.

One-minute recovery checks run even when idle and invoke Edge only for eligible work. Synchronous enqueue errors and admitted review/no-progress receipts use backoff; asynchronous lost delivery currently recovers after generation expiry without increasing that counter. Pause stops new wakes/admission, not already admitted work. Generation admission does not fence each event claim or establish hard total concurrency/fairness; event leases/idempotency protect writes. New jobs must follow the [full-app progression and handler contract](../../docs/architecture/scalable-event-processing.md#full-app-progression-for-future-agents), separating envelope schema from source revision and acknowledgment from confirmed effects. Long model/report execution requires its own durable workflow path and approval; it does not belong inside the current20-second deterministic processor.
