# Restricted record feature

Restricted page/source states use the shared WorkspaceState for loading, disabled policy, complete empty directory, incomplete choices and changed/unavailable current sources. Existing bilingual limits, factual note/retained command body, revision/provenance and private error owner stay explicit; inline record content is never reclassified as a state. State presentation adds no request, permission, selection or command. The current heading/state tests and focused source/journal/browser cases remain separate from real private API/RLS/retention acceptance.

The approved focused composition keeps one full-width current summary directory until a person explicitly opens one exact record. Title, learner/course/class, occurrence date and revision identify each permitted source; full factual note, follow-up, history and action appear only in that reader. Back returns to the same current directory row and restores its focus, or the directory heading when that source is unavailable. Current identity/revision changes withhold the selected reader instead of selecting another record. Protected denial remains local recovery; pending original commands lock Back/other editors and retain existing exact-key retry after current-source reauthorization.

Policy review captures its own visible opener separately from a record row. Back from a disabled-policy editor restores that control, with the existing workspace h1 as a focusable fallback when no directory is present. Focus recovery requires a connected, visible, enabled control; it never leaves focus on a removed form or document body.

Administrator policy review opens explicitly and is mutually exclusive with record creation/reading/review. Another pending restricted command prevents policy opening and body admission; the policy command's own retained original retry remains available. One policy receipt cannot close a different pending record action. Existing complete choice/page, private source, original revision and receipt validators remain authoritative. `styles.css` supplies only feature-owned logical directory/reader rules using Trail tokens; `apps/web/app/layout.tsx` imports it once. `test/focused-reading.test.ts` verifies summary-only/no automatic policy editor and other-command locking. Network-free actual React browser probes are retained as local evidence; real API/SQL and frozen runtime acceptance remain separate.

The Restricted workspace owns one content-first h1 through unauthorized, policy loading, denied and disabled states, with the current Refresh action attached only where already available. Synthetic-only retention and academic/AI separation limits stay beside the policy and records. `test/workspace-heading.test.ts` checks one localized heading while private records/authoring stay withheld; source purpose, policy approval, original-key commands and current role/object guards remain unchanged.
