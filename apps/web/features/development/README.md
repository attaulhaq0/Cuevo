# Recorded learning recognition

Owns personal recorded XP, source ledger/milestones, explicit admin policy/period/backfill and optional class-period alias leaderboard participation. Public ui.tsx/model.ts/copy.ts; source09/15/39/58/63/80. API owner modules/development. Parent internal queries are excluded. XP uses verified practice/revision/reflection only, never grades/attendance or a composite child score. Unknown/disabled points stay null. School approval and individual opt-in are separate; aliases/tie-safe ranks contain no learner identifiers.

Use shared session/query/form/retry/pagination and semantic tokens. Root composes shell/styles. Unit tests live under test; real source/replay/period/privacy evidence is required before acceptance. The sole `DevelopmentWorkspace` and `LearnerGoals` now use Trail goal/grow/reflection/milestone artwork through the shared public registry and `@cuevo/ui` controls. Goals remain the first action; personal recorded recognition precedes the optional class board. Staff configuration uses the same controls without learner companion art. Owner styles replace the previous border-list treatment; generic forms retain their canonical package anatomy.

Recognition reads require an explicitly chosen current authorized period. No blank selection silently opens a cross-period total or chooses another class. Summary and board reads capture actor/school/learner/period/access-generation/refresh context before parsing, then refuse a prior source envelope on the first frame. Ledger and achievement items must match that learner, period and immutable period policy. A valid recorded XP total remains independent of a review-required/null consecutive-day projection. Pagination is retained and partial lists are declared. Strict current projections reject unexpected fields; private identifiers appear only inside opened source details.

Current goal creation and review confirmation validate the strict returned goal against the journal's original course/title/planned-step or goal/revision/status/review command, then refresh. Recognition receipts require exact command/target metadata and nonnegative award counts. Invalid responses keep the original command key pending; an uncertain review can replay after current readback already shows Closed. Shared commands/drafts preserve revision bases and original payloads. Focus returns to the goal heading after valid current-actor receipt plus current goal readback, never from a historical read. Read failure clears private working input; it does not fabricate success, points or another period selection.

Every Development `CommandForm` supplies the shared pure `validateReceipt` hook. It validates the original submitted command even after a source refresh unmounts the form, while the exact journal key remains owned. Goal review retains immutable goal context and takes its expected revision from that original command; recognition derives command type and period target from its original path/body. Validators read no current journal or selection state and perform no UI/draft mutation. `onSaved` performs only current-scope refresh, confirmation and focus intent. Shared scope/key guards suppress late UI effects and protect cleared/replacement keys; a malformed domain receipt retains original-key retry rather than accepting its generic object identity.

Goal review receipts also preserve the goal's immutable creation date. A review from its original revision requires a distinct new revision source; if current readback has already reached the command's resulting revision, an original-key replay must match that exact current revision source. This distinguishes a valid delayed replay from an arbitrary source ID without rejecting a confirmed Closed readback.

No saved character/equip/catalog or costume control is introduced while its backend contract is pending. English/Arabic copy is owned by `messages.ts` and `goal-messages.ts`; logical styles cover desktop, tablet and mobile reflow. Browser/RTL/keyboard/zoom/axe and connected actual API readback remain separate root-owned gates.

Period choices show authorized names and dates. When those human labels are indistinguishable, they are unavailable pending school record clarification; the current period projection does not provide a class name, so the browser does not guess one or append a private key. Recorded-list content waits for the exact current summary, and disabled recognition shows its school-policy state instead of a fabricated empty-history claim. Duplicate board aliases use a stable rank/alias render key while preserving the exact alias-only payload.

Personal progress includes source15 consecutive recorded days from the current authorized summary, within an explicitly selected recognition period. The latest consecutive UTC day block retains its ending date, all eligible recorded days and verified recognized action count. Period-required, disabled, unobserved and review-required states keep counts/date null. Gaps describe missing authorized records only; this display does not infer effort/ability/character, award XP, change grades or add rankings. The feature parser validates real calendar dates, positive ordered counts and consistent period/state; UI uses shared tokens, localized numbers/dates and English/Arabic copy. recognition-actions browser authoring connects actual learner completion to selected-period one-day readback, mobile RTL and axe; runtime acceptance remains with root.

Policy approval uses the maximum version only after every permitted policy page has been loaded successfully. Unknown pagination/error never becomes version zero. Teachers/admins enter human milestone titles and thresholds; internal milestone keys are generated. Period choices show approved policy version/date, and current points remain recorded-action facts separate from grades.

Leaderboard participation input is scoped to the selected period and remounts when that period changes; a typed alias or opt-in cannot silently become another period's form. The selected period is locked while its command outcome is unresolved. Current owner read failure clears these private working slots; uncertain retries preserve the existing command payload.
