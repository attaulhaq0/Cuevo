# Shared web infrastructure

`api/pagination.ts` and `api/responses.ts` pass one source item to a feature parser. Array indices and page contents never become optional validation context. Actual Outcomes pagination exposed this boundary when `parseOutcome` added an explicit expected learner; pure page/list and numeric/rubric regressions preserve that independent learner check.

`holdMembershipVerification` is a browser-only continuation hold used while explicit account admission verifies its current account and claim. It suppresses premature ordinary membership requests, clears prior membership, and resumes fresh normal verification on release. It grants no access, supplies no role or session, and does not bypass any API/database authorization. The real new-user browser journey checks the console before claim and fresh workspace/sign-in afterward.

Own only mechanisms reused across features: api/client.ts and pagination/responses, session/providers and membership/Auth, query hooks, common forms/feedback/branding, and global i18n. Shared may depend on packages/ui/contracts and other shared capabilities, never feature code. It has explicit server-free imports; tests live beside the capability in test. Feature-specific response models/copy remain under features.

The shared oversized-content error gives file or record-set reduction and school-support guidance in English/Arabic. An HTTP 413 may describe an upload or a bounded read, so it does not tell every customer to divide a course. `i18n/test/content-error-render.test.ts` renders the real error component and preserves separate uncertain original-action retry and deliberate support-reference behavior. Request classification, authorization and response handling are unchanged.

`i18n/capability-label.ts` owns the English/Arabic presentation names for the existing server entitlement codes used by account access and school policy tables. Exact known codes retain distinct human feature names; unknown codes show a localized unavailable label without exposing identifiers or claiming another capability. It never normalizes authorization codes or grants access. Tests beside the helper cover supported labels and unknown, opaque and inherited-object-key inputs; rendered role acceptance remains separate.

CommandForm validates a successful receipt's object identity and runs a currently mounted feature receipt validator before settling only its exact journal key. Settlement remains available after an authorized source refresh unmounts the form. Journal subscriptions through useSyncExternalStore let remounted forms reconcile a confirmed action without resending it. Every feature-validator exception becomes an uncertain invalid receipt, retaining the original key and payload. Feature callbacks, working-input removal and announcements remain mounted/current-scope effects; an unmounted receipt does not clear working text or invoke feature behavior.

Mutation UI completion belongs to the mounted form's captured school/actor/token and exact journal key. A delayed receipt may settle its original key after unmount, while actor/sign-out journal clearing and conditional key confirmation protect replacement commands. It cannot call the feature callback, remove current working input or announce a prior save after scope changes. Original-key uncertain retries remain available to their current owner.

CommandForm select values come from the current session draft or retained command, so a temporary empty option list during an authorized source refresh cannot erase the user's selection. Confirmed saves reset controls only when the exact submitted draft is still current; a newer draft survives an earlier receipt. Invalid or removed current options still fail native required selection and server authorization; preserving working identity never grants access.

Shared authorization-error side effects also verify the request hook is mounted in the same captured school/actor/token context. A late prior-session401/403 remains sanitized but cannot clear the current session's drafts or trigger its access refresh.

Each CommandForm field describes its sanitized form-level error through aria-describedby. The API does not currently provide trusted per-field error detail, so the UI does not assert that every field is invalid. Native required/range validation and sign-in credential associations remain specific to their fields.

Session-owned form-drafts retains only typed working values and explicit expected-version fields. It never caches protected read responses. Scope is current school, actor and form endpoint; offline, sign-out, current access denial and owner read failure clear the relevant drafts. Save and submit can share a working-input key while keeping distinct command journals; stale version fields are sent only when present in the current payload. Confirmed mutations announce a sanitized persistent status, and source/support IDs are available through deliberate disclosures.

Changing language clears the transient saved-action notice from the prior language. It preserves the domain receipt, private working values and retry ownership; it does not re-execute the action. The rendered regression lives in `tests/e2e/customer-navigation-context.spec.ts`.

use-child-context and ChildSelector load the current authorized child directory, require explicit selection for multiple children, and keep that selection only in the browser session. Content owners request the selected child's report/portfolio through existing authorized endpoints. An absent or revoked directory selection never falls back to a result-derived child.

Each successful membership revalidation advances accessGeneration. Protected query hooks reconcile their current source and child scope on that generation, including browser focus and periodic rechecks. Owner read failures clear both endpoint-based working slots and exact semantic assessment/community slots; unrelated room and actor inputs remain scoped.

`session/capabilities.ts` declares browser-safe destination prerequisites used by shell and home. CommandForm optionally reports pending/uncertain locking through onLockedChange. `session/navigation-intent.ts` defines browser-safe exact owner/source navigation and URL parameters. It validates structure only, while destination APIs reauthorize the selected current source. It imports no feature implementation.

CommandForm supports optional regionLabel/asRegion for accessible naming only. Repeated assessment/content forms can use ordinary semantic sections with visible headings and authorized human context; important navigation regions retain unique labels. Submission/retry/session/confirmation semantics stay unchanged. Actual role/axe/browser checks verify affected contexts; no broad accessibility rule suppression is used.

api/people.ts provides browser-safe currentLearnerChoices for owned selected-learner flows. It preserves names/full class labels, filters student records and flags identical or missing context without identifier suffixes. Owners combine it with complete current paginated retrieval before requesting a selected learner's private context; self reads need no directory.

`diagnostics` owns current-session synthetic QA observations. Collection begins only after the authorized API returns strict enabled configuration. Request hooks report fixed outcome/timing categories and parser failures through their captured mounted actor/school/token/access-generation guards. Runtime listeners classify errors locally; known React hydration text and production error418 can become a fixed hydration category, while other runtime messages remain a general fixed category. Raw values never enter a diagnostic. There is no browser PostHog SDK, replay or autocapture. The in-memory reporter deduplicates six-field observations and admits at most20 per current actor/school/token/access-generation scope, including at most5 success samples so successes leave room for15 failures. It uses direct nonrecursive requests and aborts/configuration-clears on session, actor, school, access-generation or offline changes. These are bounded diagnostic samples, not a complete request/error census; initial preconfiguration hydration and observations beyond the budgets are omitted. Locale/viewport are read after mount. API/SQL remains the current policy and source authority; no browser queue or persisted diagnostic content is retained.
