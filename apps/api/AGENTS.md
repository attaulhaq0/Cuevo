# API contributor instructions

Inherit root AGENTS.md. Read this app README, docs/codebase-map.md, the affected module README and source specifications before coding.

- Keep main.ts/app.ts and serverless.ts for runtime/HTTP composition; hosted adapters must reuse createApp rather than duplicate routes or domain authority. Domain controllers/services live under src/modules and infrastructure under src/platform.
- Platform cannot import domain modules. Modules consume packages through @cuevo public exports; cross-module imports require a documented public.ts surface.
- Reuse verified identity/current-session and actor transaction boundaries. Every protected query, mutation and replay checks current tenant/entitlement/role/relationship/object scope.
- Hosted synthetic staging filters current memberships before customer label disclosure and repeats the narrow populated synthetic/current-member admission check in every supplied-school transaction before its domain callback. Never replace these gates with frontend hiding or a startup-only assertion. Production API SQL always uses verified TLS; URL options cannot override it.
- Keep authoritative SQL changes in append-only supabase/migrations and verify grants/RLS. Do not expose helpers through browser Data API as a shortcut.
- Curriculum owns immutable per-course source approvals; academic owns scoped approved-reference reads. Keep programme/source identity and generated academic result reference identity distinct, and retain course serialization around configuration/approval.
- Period objective plans consume the school-owned current period helper and pin its revision; maintenance lock precedes course/plan locks. Recorded teaching, declared task inclusion and current native evidence are separate sources, with explicit unknown denominator when no plan exists.
- Curriculum lifecycle has one persisted history and explicit review provenance. New configuration and academic write availability are separate from current authorized retained-source reads; retirement cannot delete historical evidence authority. Serialize lifecycle/configuration before course and native mark/source locks.
- Learning/academic consume accepted curriculum behavior only through curriculum/public.ts after current scope, revalidating locked bytes/digest and deterministic native model/scale/rubric. Generic School Custom review is source data; no customer/curriculum code branches or guessed official rules.
- School campuses do not grant access. Private approved support reads require exact current learner/course/assessment purpose; teachers receive instructions, approvers alone receive private approval notes. Explicit student/parent publication and date windows never establish diagnosis or grade authority.
- School learner profiles expose exact current identity/enrollment/published course names under current person/class/programme scope. Capacity overflow requires review; private notes/guardian directories/academic aggregates remain separate domain projections.
 - Restricted records are a separate purpose owner with default-disabled explicit entitlement and synthetic school-authored policy. Teachers/admin policy owners use exact current source; parents/students/coordinators and general audit do not receive protected notes or incident existence. Never import this owner into academic/state/intelligence/profile.
- Academic selected gradebook releases reauthorize every current learner/source/mark/policy in one transaction and emit the normal event/evidence per result; preserve all-or-none rollback and stable course/release/source lock order.
- Independent parent result publication uses the exact shared native result ID and current ledger before every parent result/evidence/history/portfolio read. Keep release-time parent approval immutable; current sharing and grade authority are separate.
- Portfolio organization retains existing evidence/item identity. Collections/placements are learner-owned; feedback requests pin the exact current reflection and queue reads repeat native source/current teacher authority. Resolve requests through existing immutable human review; no raw parent/coordinator request or submission access.
- Unit/contract tests: test/unit. Real Auth/API/Postgres tests: test/integration; run sequentially because revocation fixtures intentionally change current relationships.
- Recommendation page optimization may share only full identical immutable proposal/run/saved-source authorization inputs within one statement. Preserve exact current source, policy, publication, synthetic population and relationship denials; never replace them with a baseline-only/TTL verdict or expose raw context in page responses.
- Update module navigation and run architecture, typecheck, lint, relevant API/SQL and build checks. In-progress improvement work must not be silently altered or declared complete during refactors.

- Portfolio page identity may consume only the exact source object just authorized by the canonical portfolio_source function, through an ungranted owner-only helper. Canonical identity, command and replay paths must keep source checks; parent pointers, source publication, current human/duplicate-name context and artifact metadata remain exact per row.

- Recommendation page source verdict maps remain owner-only and request-local. Full argument tuples and pinned canonical delegate bodies preserve per-run facts/current source/policy/native authority; never expose the map, persist it, substitute a partial key or reuse it for mutations/replay.
- A canonical source/security helper change must regenerate and independently review its page delegates in an additive migration and rerun exact source/payload/denial parity. Merely updating SQL193 expected hashes is insufficient and must not conceal stale page authority.
