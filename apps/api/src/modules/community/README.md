# Safe school community

Public factory createCommunityController(identity,database) from community.controller.ts registers /v1/community. community.service.ts owns strict schemas, actor capability and bounded source commands/queries. SQL sources own current room/class/group/restriction scope, moderation and durable events. Sources11/15/19/39/43/61/80/81 and the Technical MVP decision apply.

Current class rooms and teacher-led groups require community entitlement, current membership and enrollment/teacher assignment. Groups have explicit teacher-managed rosters; no public profile, foreign-school friendship or direct student chat exists. Narrow roster queries return display names/roles for current room members and do not broaden people RLS. Parent has no discussion access and receives only explicitly parent-visible current child announcements. Posts/reports/moderation/restriction/read receipts preserve immutable history; reactions/member configuration are authorized idempotent state. Fixed per-actor limits bound new post/reaction/report actions. Current restriction/relationship scope precedes replay.

Realtime receives only minimal room invalidation identifiers on private channels. JWT subject/session_id is checked against current auth.sessions/user status and stored room membership in realtime.messages SELECT RLS. Client INSERT/Presence publishing is denied. Permission caches persist until rejoin/JWT refresh, so no protected post content is broadcast; every refresh/reconnect reconciles through currently authorized API queries. Product-level Allow public access must be disabled in Realtime settings by deployment/local setup. No client channel is an authoritative mutation path.

Root worker dispatches community.post_created/community.changed/moderation.reported to internal.process_community_event(eventId,leaseToken). That private function resolves stored source/audit, calls realtime.send with private=true, verifies its stored minimal message and atomically persists receipt/ack. A send failure retries rather than declaring completion. Tests: apps/api/test/unit/community-service.test.ts, integration/community-api.test.ts and SQL080. Database and actual join/revoke/reconnect checks are scheduled by the integrator with background workers stopped during rollback SQL fixtures.
`GET /announcements/:id` reads one exact current authorized announcement through an API-only helper. Notification list titles come from the same school-scoped authorized source rather than a separately paged browser cache. Source and receipt reads retain current community/guardian/class approval; no parent room access or raw table grant is added.

ParentConversationController / ParentConversationService own school-approved adult communication inside community. Current guardian, enrolled child and exact class/subject teacher tuple is verified for every create/read/send/replay, and mutation locks retain those exact relationships through commit. A versioned administrator policy defaults disabled. Immutable messages/read confirmations/reports/moderation/pause history stay private with no raw API/Data API/worker reads. DELIVERED_IN_APP means committed availability only; external messaging remains unconfigured. Pause blocks new messages while permitted history/reconciliation remains readable; current policy or relationship revocation removes future reads and replay. School moderation has explicit purpose here and does not establish access to pastoral categories.

Controlled community maintenance owns immutable group rename/close/reopen, report review outcomes and announcement correction/withdrawal. New purpose commands have current teacher-owner/admin/class scope, expected versions, reasons, explicit confirmations, audit/outbox and singular original-key replay. Closed group history uses a separate current-member read predicate; live posting/reactions/private-channel access deny. Announcement current approval/withdrawal is evaluated before paging, and read receipts name the exact revision so a correction remains unread. Raw source ledgers remain private/FORCE RLS/no-truncate. Existing minors/network restrictions and parent child announcement policy remain unchanged. Actual SQL/API/browser checks remain root scheduled.

Direct mention notifications use immutable explicit current-member links and exact visible source reads. They are separate from announcement revision identities/read receipts. Parents remain excluded from pupil mentions. Recipient choices are at most five, schema-validated, current same-room roster sources; arbitrary @text carries no authority. Source hiding/restriction/revocation removes future content/receipt access. Low-risk deterministic in-app delivery uses post/audit/outbox, with no email/push or public network. Actual API/SQL/browser verification remains root scheduled.
