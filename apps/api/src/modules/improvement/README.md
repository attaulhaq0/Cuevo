# Improvement domain

Entry: improvement.controller.ts. Public runtime interfaces createImprovementController(identity,database,intelligence?) and createIntelligenceService(identity,database,config) from intelligence.service.ts. orchestrator.ts validates minimized native evidence and a strict factual/action schema; fixture-provider.ts implements the explicitly local deterministic provider. Product source IDs 10, 12, 21, 38, 39, 60, 78 and 81 apply.

Preserve teacher-authored vs AI-generated origin, HUMAN/FIXTURE/LIVE generation mode, linked run provenance, human approval before intervention, current scope before replay, immutable decisions/completions and compatible source timing for follow-up measurement. The Technical MVP decision permits explicit fixture execution only in local/test with approved school policy. Live AI remains unavailable without an approved adapter/configuration; fixture evidence does not certify model quality. Generation occurs outside a database transaction and current identity/source is rechecked before persistence.

Tests: API unit/improvement-contract.test.ts, improvement-orchestrator.test.ts, intelligence-evaluation.test.ts and intelligence-service.test.ts; integration/improvement-api.test.ts and intelligence-api.test.ts; SQL 060/062. Private transactional behavior lives in append-only migrations. Intelligence runs store only explicit source IDs/native facts, a permitted read-tool trace, configuration versions and usage/failure metadata. Provider output cannot add free-text learner facts, tools or authoritative mutations. Outcomes report observed raw-score change and limits, never causal certainty.

Product source lookup: [task context map](../../../../../docs/product/context-map.md); numbered IDs resolve through the product registry.

New Teacher Insight runs call begin_teacher_insight_run and retain an immutable supplemental context in intelligence_context_details. Current authorized course/reference/results, processed practice/revision/reflection, prior intervention outcomes and teacher-authored learning options are bounded and rechecked before completion. A selectedActivityId must match the exact stored option; the server copies its title/instructions before the immutable command receipt is finalized. Legacy numeric runs remain unchanged. GET /v1/intelligence/runs/:id/context discloses historical source context only to current authorized teacher/admin and rechecks policy/source scope. Shared InsightContext schema lives in @cuevo/contracts; browser code never imports the server implementation.

GET /v1/intelligence/metrics reports mode/window/current-authorized-run counts with explicit rate denominators, cost and latency. No records yields null rates. Acceptance, completion and observed improvement use their separate domain denominators; unsupported claim/leakage/tool/override rates remain unknown without a dedicated observed evaluation denominator. Fixture metrics describe local mechanics and do not certify live-model quality.

Historical Teacher Insight disclosure and original-key replay reauthorize every stored source through require_stored_insight_scope. Stored IDs/immutable factual fields remain independent of a changing current top-N context page: adding an authorized option does not revoke old context, while a no-longer-current saved result or denied source prevents disclosure. Legacy runs without supplemental context retain their original boundary. Metrics are teacher/admin only and count measured outcomes only when baseline/follow-up source and current programme authority are valid; coordinator class summaries are a separate purpose-bound view.
