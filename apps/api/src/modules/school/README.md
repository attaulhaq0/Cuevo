# Current-school operations

Public runtime surface: createSchoolController(identity,database) from school.controller.ts. SchoolService owns current-school context, bounded setup/operations queries and purpose-specific commands; no other app implementation is imported. Sources 07/14/18/38/39/44/61/64/81 and the Technical MVP decision apply.

The /v1/school namespace exposes current school details, academic years/terms/year groups/classes/subjects, already-provisioned memberships, teacher/enrollment/guardian windows, attendance, timetable/calendar/report periods and approved privacy/recognition policy. school.operations entitlement and current role/object scope are required. Admin setup commands never create tenants, issue entitlements, provision Auth users or attach foreign identities. Existing same-school Auth users alone can be configured; access changes require explicit human confirmation and current admin self/last-admin protections. First-tenant synthetic identity creation remains the guarded privileged local bootstrap.

SQL source functions validate current tenant/admin/object scope before stored replay and perform mutation/audit/outbox/receipt in one transaction. Parent attendance/upcoming reads default closed until a versioned explicit school approval; current guardian relationship is checked each read. Staff attendance notes are excluded from parent/student projection. Attendance is immutable factual history with reviewed corrections and never academic/Habit/intelligence evidence. Timetable conflicts are deterministic; no official attendance/grading rule is invented.
