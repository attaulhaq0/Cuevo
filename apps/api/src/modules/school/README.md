# Current-school operations

Public runtime surface: createSchoolController(identity,database) from school.controller.ts. SchoolService owns current-school context, bounded setup/operations queries and purpose-specific commands; no other app implementation is imported. Sources 07/14/18/38/39/44/61/64/81 and the Technical MVP decision apply.

The /v1/school namespace exposes current school details, academic years/terms/year groups/classes/subjects, already-provisioned memberships, teacher/enrollment/guardian windows, attendance, timetable/calendar/report periods and approved privacy/recognition policy. school.operations entitlement and current role/object scope are required. Admin setup commands never create tenants, issue entitlements, provision Auth users or attach foreign identities. Existing same-school Auth users alone can be configured; access changes require explicit human confirmation and current admin self/last-admin protections. First-tenant synthetic identity creation remains the guarded privileged local bootstrap.

SQL source functions validate current tenant/admin/object scope before stored replay and perform mutation/audit/outbox/receipt in one transaction. Parent attendance/upcoming reads default closed until a versioned explicit school approval; current guardian relationship is checked each read. Staff attendance notes are excluded from parent/student projection. Attendance is immutable factual history with reviewed corrections and never academic/Habit/intelligence evidence. Timetable conflicts are deterministic; no official attendance/grading rule is invented.

Contracts live at @cuevo/contracts school exports. Unit tests live in apps/api/test/unit/school-*; real Auth/API/Postgres journey in test/integration/school-operations-api.test.ts; SQL070 checks permissions, source/access denial, idempotency, parent approval/revocation and history. Technical completion awaits scheduled DB/browser evidence and independent review.

Named daily pages reuse existing school-list authorization and enrich only admitted rows with authorized learner/class/year/subject/teacher labels. Selected child schedule reads require that child’s current enrollment rather than inheriting a sibling’s class. `attendance-roster` is staff-only, bounded and selected-class scoped; no parent directory or staff note grants are added. Migration20261001210853, SQL153 and customer-school-context-api cover this boundary.
Current calendar/timetable/report-period lists resolve append-only maintenance revisions before current ownership/publication/selected-child authorization and paging. The private `current_school_schedule_page` helper has no direct runtime or Data API grant; `named_school_page` remains the application entrypoint and enriches only authorized current rows. School context reuses the same named projection. Original tables/RLS remain historical. SQL166 and maintenance API regression cases cover original-private→current-approved publication, class moves, cancellation and bounded continuation.

Current membership/enrollment/teacher/guardian rows have monotonic revisions and private immutable source history. Existing configure routes require expectedRevision for updates and0 for creation; missing update basis fails. Same-key reconciliation rechecks current administrator/provisioned source before returning its original receipt. UI retains the original reviewed revision across same-source refresh and changes basis only when selecting a different exact relationship tuple. SQL169 and school-access-concurrency API/browser cases cover stale access restoration and explicit current review. Privileged fixture/source maintenance also advances revisions; bootstrap retains no raw API write grant.

`support.controller.ts` owns campus/class-campus context and private approved instructional support. Campus assignment is versioned; retirement refuses active assigned classes. Support has exact learner/course/optional task, explicit window and separate learner/parent publication. Only approvers receive private approval reasons; assigned teachers receive instruction text. Learner/parent reads require a selected current course/task plus exact learner/guardian/programme and current published content. Source-specific outbox validation acknowledges actual object/actor/revision; no diagnosis, grade or AI authority is introduced. School-support contracts, SQL172 and campus-learning-support API/browser verify this boundary.

`profile.controller.ts` exposes a separate exact learner identity/current enrollment/current published course projection. Current person/class/course/programme authorization and school access serialization apply; peer and withdrawn teacher scope are denied. It contains no guardian directory, approval notes, diagnoses, inferred traits or scores. Capacity overflow requires review instead of silently truncating. SQL174 and learner-profile API/browser cover current and transferred contexts; school instructional support stays in its own purpose-controlled surface.

`automation.controller/service` owns the read-only current administrator policy/execution review. It exposes only fixed implemented policy families and bounded allowlisted queue/receipt state, with explicit window/truncation and safe error summaries. Source payloads, learner identities, restricted/pastoral/support records and provider context remain excluded. No new rules, worker retries or consequential automation authority is added; existing domain policies/forms and human approvals remain decisive. Source11/37/39/81/83, SQL177 and actual automation API/browser accompany the surface.
