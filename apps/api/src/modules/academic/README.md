Teacher-defined School Custom rubric versions are course-owned immutable definitions with 1–30 criteria and 1–20 allowed named levels per criterion. POST /v1/rubrics creates a complete version; GET /rubrics and /rubrics/:id return current course-authorized definitions. POST /assessments/:id/rubric pins a same-course definition and advances the assessment policy only before any numeric or rubric mark. Existing numeric source tables/functions remain authoritative for numeric results. Native rubric marking/results/evidence/current projections have companion tables; a guard forbids writing a scalar numeric mark for a rubric assessment.

The existing /submissions/:id/results command accepts numeric score or native rubric choices, never both. Complete criterion choices must match the pinned definition and allowed levels; the server snapshots native labels/descriptions in definition order. /results/:markingId/release dispatches to the matching immutable source path, and /marking, /results and /evidence/:id expose the model explicitly. Rubric results contain nativeResult.type rubric, rubric/version/policy and criterion choices, with normalized null and no score/maxScore. Human release creates source evidence and a current pointer atomically with audit/outbox/idempotency; correction preserves former native evidence. Parents see only explicitly released approved projections under current guardian relationships and cannot read rubric drafts/definition authoring. Numeric improvement comparisons cannot use companion rubric result IDs without a separately approved comparable policy.

Rubric source events are rubric.created, assessment.rubric, rubric.assessment.marked and rubric.result.released. Worker native rubric projection and learning assessment read/browser model integration are coordinated companion work. Backend source/SQL tests alone do not establish the browser/worker/gate acceptance. This is synthetic School Custom behavior, not official curriculum approval.

Parent current result pages use internal.list_parent_current_results(integer,uuid), a parent-only private source read that resolves current approved child relationships and published course access once before bounded numeric/rubric current rows. It preserves explicit parent visibility, source evidence/reference version and native form, and does not change table policies or grants. This avoids repeated correlated RLS work in the historical current-pointer join plan. Mark/release replay additionally requires current_submission_open; returned, closed or superseded source receipts cannot authorize new academic actions while historical evidence remains readable.

Other role result pages use internal.list_current_native_results(integer,uuid) with the same bounded source projection. Students resolve self; teachers resolve currently assigned/enrolled active learners; coordinator/admin resolve tenant-wide retained directory history. All roles retain current course read scope and exact source/reference/native integrity. This replaces pathological repeated-policy join work without increasing result visibility. Both reads return current released rows, at most 100 plus a sentinel before response slicing and a 500KB cap.

GET /v1/learners/:id/academic-report returns a strict version1 current released page for one selected learner. The existing numeric/rubric native source projections accept selected learner scope before pagination; legacy list functions forward to those same active implementations. Every read rechecks current role/tenant/capability/relationship and exact approved parent child projection. Native values, teacher feedback, evidence/source/reference/policy/revision/date are preserved; no overall percentage, completeness, attendance/development summary or official transcript is inferred. The envelope declares CURRENT_RELEASED_PAGE and NOT_ESTABLISHED coverage even when no further authorized page exists. Contracts reject another learner, duplicate source IDs and mismatched native policy/value. Tests: unit/academic-report.test.ts, integration/academic-report-api.test.ts and SQL105. Fresh browser export is owned by the progress feature and escapes source text into a bilingual standalone HTML document.

GET /marking uses private internal.read_current_marking_page rather than multiplying protected submission/current/assessment/person RLS joins. The function resolves managed/readable staff course scope once, authorizes current exact submission/enrollment/programme/student candidates before a100+1 materialized page, then loads numeric/rubric/latest-mark details. Returned and closed current sources remain visible with their explicit lifecycle; this read grants no new marking/release authority. Superseded submissions are omitted. The500KB source cap and five-second runtime budget remain unchanged, and browser/worker receive no execute grant. SQL110 exercises101 authorized source rows, one other-owner source, cursor correctness, returned/closed state and current enrollment/teacher/role/tenant denials. The source history and existing RLS policies remain unchanged.

Current parent native result pages require the result learner's exact active enrollment in the source course class in both numeric/rubric candidates before pagination. A linked sibling may authorize the course itself but cannot authorize a withdrawn child's current result. Selected report and current list now use the same conservative current-object policy. Retained approved historical evidence reads keep their established current guardian relationship/programme/source policy.
