# School and learning domain

Entry: learning.controller.ts; learning.service.ts owns course/unit/lesson/activity/assessment/submission queries and commands. Reuse platform identity/database and shared contracts/domain rules. Sources: product source IDs 07, 13, 14, 17, 38, 39 and 43.

Preserve current class/subject/enrollment scope, explicit publication, original-key replay and source immutability. Tests: API test/unit/school-learning-contract.test.ts, test/integration/school-learning-api.test.ts and supabase/tests/030_school_learning.test.sql. Public runtime interface is createSchoolLearningController(identity,database); schema authority remains migrations. Native grading/curriculum behavior belongs in the academic/source context, not hard-coded customer branches.

Submission lifecycle uses immutable app.submissions revisions plus current_submissions state, learner-owned mutable drafts, immutable teacher returns and closure records. Initial submission consumes any draft; return records explicit human feedback, resubmission creates a new source pinned to that return and prior source. Older released evidence still points to the original submission. Lists expose current sources; /submissions/:id/history exposes authorized bounded history. Current-source academic insert guards lock and reject RETURNED/CLOSED/superseded sources without rewriting academic history. Academic queue integration is composed by the root owner; historical baseline authorization is deliberately retained.

Assessments have operational availabilityVersion independent of frozen academic policyVersion. Availability is OPEN/CLOSED, optional start/end and explicit allowLate; defaults remain open/late accepted. Every learner source write and replay rechecks current published course/enrollment, entitlement and availability. /assessments/:id/draft supports server DRAFT state; /submissions/:id/return, /resubmit and /close provide explicit source transitions. Only actual feedback-linked resubmission is eligible for revision observations; teacher grade corrections remain distinct.

Teacher-authored single-choice quizzes have immutable versioned questions/options/private correct keys, explicit publication and immutable answer attempts. Student published reads omit answer keys; authoring reads remain teacher/admin scoped. Quiz attempt submission creates an immutable answer-source submission and CHECKED_NOT_GRADED per-question notes, without authoritative grade release. One attempt per published quiz/learner is supported in this bounded increment; quiz returns/retries with changed answers are denied. Teacher review/release uses the academic domain. API mutation receipts, audit and source event writes share the actor transaction and original idempotency key.

New tests: unit/learning-lifecycle-contract.test.ts and learning-lifecycle-service.test.ts, integration/learning-lifecycle-api.test.ts, SQL035_submission_lifecycle_quiz.test.sql. Event kinds: submission.draft_saved, submission.returned, submission.resubmitted, submission.closed, quiz.created, quiz.published, quiz.submitted and assessment.availability. Root coordinates worker observations, academic queue and browser integration; backend unit/build results are not end-to-end verification.

Current submission queues and /submissions/:id/history use internal.read_submission_page(integer,uuid,uuid). The source function resolves current admin/teacher-owned course or enrolled student-self access once, bounds source rows before joining names/return feedback, and excludes parent/coordinator raw-work access. It preserves current pointer state and immutable historical contents while avoiding repeated policy joins that approached the request timeout on modest accumulated fixtures. Source page limits and 500KB response cap remain explicit; no table grants/RLS are changed.

Product source lookup: [task context map](../../../../../docs/product/context-map.md); numbered IDs resolve through the product registry.

Assessment list metadata resolves a rubric assessment's pinned identity through internal.read_assessment_rubric_identity after current assessment/course authorization. This exposes only the UUID required by the model contract to permitted parents/readers, not rubric definitions or marking criteria. Parent definition-table policies remain private. SQL125 and actual Auth parent-assessment-metadata-api verify the identity, current guardian/tenant denials and no private definition access.
