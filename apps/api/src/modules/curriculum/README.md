# Versioned curriculum contexts

Public surface: createCurriculumController(identity,database). Sources 05/06/07/26/34/50/55/66/69/76/81/83/85 govern the /v1/curriculum boundary.

Current school admin/coordinator explicitly creates immutable source/version contexts, synthetic reference hierarchies, programme instances and learner/course assignments. Curriculum, jurisdiction and quality remain independent axes. Course configuration checks class/subject/year/reference version and creates an explicitly approved School Custom reference; it cannot activate an official pack. Official dossier metadata is stored only as REQUIRES_REVIEW/SOURCE_RESTRICTED/UNKNOWN. Source rights, academic review and customer claims require separate locked artifacts; no content or grading facts are guessed.

SQL source functions own scope-before-replay, idempotency, audit/outbox and immutable used contexts. Browser and worker have no configuration writes. Protected reads are staff-scoped. Contracts and real SQL/API golden cases verify mismatches, cross-tenant denial and no false official activation. This module is part of the technical curriculum architecture; it does not assert publisher support.

packs.ts provides loadLockedPack, createPackAdapter and importLockedPack for server-only local artifacts. It validates real paths/byte limits/SHA256 for every required source file, strict JSON/hierarchy/mapping/native semantics, synthetic rights and pending official/customer status. Bundles live in supabase/seed/curriculum with one approved synthetic primary and alternate pathway. Script-owned guarded reference scenario seeding exercises exact programme assignments and numeric/rubric source flows. Tests curriculum-pack/reference-scenarios cover traversal, tampered bytes, native version mismatch and local target/missing-evidence semantics. Stored source registry metadata cannot replace file-byte validation or external academic approval.

Import traverses every reference parent before its child independently of artifact array order; a missing parent is rejected rather than written as null. The adapter exposes native subjects by exact optional version/stage context and validates course reference ancestry, subject, stage and version. Course validation returns VALID/REQUIRES_REVIEW from locked facts only; it grants no database access or official approval. The existing database configuration command remains the current actor/class/year/subject authorization boundary.
