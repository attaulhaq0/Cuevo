Knowledge dimensions and AI classification are deferred. Contract and catalogue tests are scoped evidence; compiled delivery and actual API/SQL/browser acceptance remain separate.

Runtime still checks real-path containment, bounded bytes and immutable manifest/source/rights hashes. The lower-level explicit-root loader remains for guarded import/test workflows. Workspace and compiled artifact path checks prevent root-cwd tests from hiding broken ordinary development startup.

It validates real paths/byte limits/SHA256 for every required source file, strict JSON/hierarchy/mapping/native semantics, synthetic rights and pending official/customer status. Script-owned guarded reference scenario seeding exercises exact programme assignments and numeric/rubric source flows. Tests curriculum-pack/reference-scenarios cover traversal, tampered bytes, native version mismatch and local target/missing-evidence semantics. Stored source registry metadata cannot replace file-byte validation or external academic approval.

Import traverses every reference parent before its child independently of artifact array order; a missing parent is rejected rather than written as null. The adapter exposes native subjects by exact optional version/stage context and validates course reference ancestry, subject, stage and version. Course validation returns VALID/REQUIRES_REVIEW from locked facts only; it grants no database access or official approval. The existing database configuration command remains the current actor/class/year/subject authorization boundary.

`lifecycle.service.ts` owns explicit `/versions/:id/lifecycle` reads/transitions. One immutable lifecycle applies to new School Custom contexts (DRAFT→reviewed APPROVED→ACTIVE→SUPERSEDED/RETIRED) with current admin/coordinator confirmation; previously active synthetic configuration is retained by a compatibility entry. SCHOOL_AUTHORED review validates the saved complete school hierarchy, while LOCKED_ARTIFACT adds actual byte/schema/hash validation and exact stored hierarchy comparison through the existing loader. Both remain technical-only; official metadata cannot activate. Supersession requires an active same-pack/programme/scope replacement, blocks new configuration and preserves ongoing work. Retirement refuses open tasks/submissions/assigned support, then private database write guards keep bound work read only while current authorized evidence/history remains readable. See the lifecycle/retained-authority ADR, SQL164, lifecycle API/browser and adapted source-fixture review commands.
