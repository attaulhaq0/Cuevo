# API platform

`identity/identity.service.ts` resolves verified sessions/current stored memberships. `identity/supabase-auth.ts` verifies tokens with Auth. `database/database.ts` supplies bounded pools and actor/school transaction context. Platform code depends on domain/contracts/config public packages, never application domain modules. Tests live in apps/api/test/unit and integration.

createApp supplies explicit TLS certificate verification to Database for production and exact project-bound hosted synthetic staging. NODE_ENV or the deployment production label requires completeness/HTTPS/TLS independently. The server-only optional reviewed CUEVO_DATABASE_TLS_CA supplements system trust; PostgreSQL URL options cannot override verification. Local pools retain their existing behavior. Unit pool settings verify configuration, while actual hosted TLS remains a separate acceptance gate.

Hosted synthetic createApp filters current memberships before school/person label disclosure. Database actorTransaction repeats internal.synthetic_school_runtime_allowed for every supplied school before the domain callback. It checks current membership/school-context entitlement and the private populated entirely synthetic school precondition; missing/false/unavailable admission never runs a protected read, mutation or replay callback. Session-only transactions remain user-scoped. Append-only20261002223437 exposes only this boolean to cuevo_api; no raw population or worker grant is added. SQL18816 and actual synthetic-staging-runtime-api verify mixed/missing/revoked denial, unchanged audit/outbox/key counts, same-key recovery and ordinary local behavior.

Product source lookup: [task context map](../../../../docs/product/context-map.md); numbered IDs resolve through the product registry.

`request-limits/request-limits.ts` applies fixed one-minute read/write and connection-address budgets before protected routes perform Auth/database work. It stores bounded hashes in process memory, ignores untrusted forwarding headers, and returns a sanitized 429 with Retry-After. It supplements domain-level community limits and current authorization. It is a single-process safeguard; shared production gateway limits require deployment policy.

Database actor transactions record only fixed outcome, elapsed time and pool waiting count. SQL strings, parameters, actor identifiers and database errors stay out of timing telemetry. Request telemetry records fixed route templates/status/correlation; worker telemetry records queue lag and delivery outcomes. These records support local investigation; production alert delivery remains a deployment concern.

`health/readiness.ts` shares one in-flight dependency probe and caches its sanitized result for two seconds. Public readiness uses a separate per-address budget; changing bearer/query values cannot bypass it. Liveness remains inexpensive. API production configuration checks only API-owned credential consumers, avoiding distribution of the worker password merely to pass startup validation.

`telemetry/browser-diagnostics.controller.ts` exposes current-session configuration and fixed-field QA observations. Identity and the private SQL source recheck current school access, latest analytics policy and explicit active all-synthetic school activation. A random version-four diagnostic identity is its exact retry key; one source/audit/outbox commit is idempotent. Six enum fields describe category, feature, status, timing, locale and viewport. Raw errors, URLs, content, request data and selected-child identifiers are rejected. Private source rows have forced RLS and function-only API grants; recording is bounded to20 observations per actor and500 per school per minute. Outbox acknowledgment validates the immutable source but is separate from destination delivery. Product sources11/39/42/81/82 and SQL/API deny tests govern this boundary.
