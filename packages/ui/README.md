# Shared design system

Public API: @cuevo/ui for Button/Status, @cuevo/ui/tokens.css for semantic tokens. Component stories are colocated under src and previewed using apps/web/.storybook. No school-specific rules, server credentials or application imports belong here. Feature-specific UI remains in its owning feature. Preserve keyboard, reduced motion, Arabic/RTL and shared design tokens.

## Authenticated Trail foundation

The existing `.workspace` root is the boundary for the canonical Trail token overrides and primitive anatomy. The root/global token definitions and approved authentication styles remain unchanged. Workspace color and typography are applied at the boundary so inherited body values do not override the scoped palette. Default presentation is light; `data-theme="dark"` selects navy surfaces and `data-theme="system"` follows the browser preference using scoped `color-scheme` and `light-dark()` pairs. Auth keeps its existing light color scheme. Theme preference storage, pre-paint resolution and shell controls are owned by the web app and remain pending integration.

`data-density="compact"` reduces spacing while retaining 44px control targets. `data-motion="quiet"` and the system reduced-motion preference set interaction durations to zero. Material tokens distinguish opaque reading/raised surfaces, opaque chrome and a scrim; background artwork and shell geometry remain with their existing app owners. Keep the current Latin/Arabic font stacks until reviewed font assets are available.

The current `Button` primary/secondary/quiet variants and `Status` neutral/positive/warning props retain their native behavior. Their geometry, disabled palette, focus, fields and pressed-button/tab anatomy are scoped to `.workspace`. Native field types, IDs, associated errors and form ownership remain the caller's responsibility. Checkboxes/radios preserve their native control shape. Existing semantic groups (`role="group"` with direct `aria-pressed` buttons) and tab lists share the canonical selection treatment; no feature selector or alternate tabs renderer is introduced. A semantic tab list still requires its owner to implement the appropriate keyboard behavior.

Fields, pressed-button groups and the existing shared `CommandForm` classes now have their one authenticated anatomy here. The superseded generic Learning stylesheet definitions are removed; form grids, full-width fields, fieldsets, actions, notes and mobile reflow stay shared. Community reaction forms keep a scoped compact layout override because their purpose is a single reaction action. Field semantics, current selections, scope, commands, receipt validation and error associations remain with their existing owners. Portalled workspace dialogs/popovers must retain the authenticated token boundary. These tokens alone do not implement all-role layouts or establish dark-mode acceptance.

The `Foundation/Trail` Storybook stories show Light, Dark, Compact, Arabic and Quiet controls in an explicit workspace boundary. Existing auth-related foundation stories remain intact. `node node_modules/vitest/vitest.mjs run packages/ui/test` exercises native Button/Status forwarding, controlled icon destinations, filled/outline fallback and measured text/control contrast constraints against the actual workspace colors. Browser focus/activation, responsive/RTL/zoom and auth visual comparison remain separate acceptance gates.

## Controlled icons

`CuevoIcon` is the controlled utility icon registry, with named metaphors, shared optical size/stroke and hidden decorative semantics. New names are added here rather than arbitrary feature icon imports. The supplied logo/reference establishes shared cool-blue canvas, navy typography, contrast-safe blue/teal actions, focus and controlled elevations; raw image colors are identity accents and never assumed contrast-safe body text. Disclosure summaries share visible keyboard focus with buttons/fields. All-theme whole-app migration is still open.

The approved illustration's book, pencil, feedback, rounded bars and role glyphs use `variant="filled"` in the same registry. These scalable vectors retain the reference's optical mass and silhouette; utility/form icons retain the controlled outline treatment. Semantic illustration colors are decorative accents with adjacent text, not contrast-safe body-text colors. Extend this family centrally instead of introducing a second icon library.

Supported workspace/action names now include `home`, `learning`, `community`, `portfolio`, `assessment`, `development`, `curriculum`, `school`, `settings`, `notification`, `search`, `calendar`, `goal`, `reflection`, `close`, `check`, `refresh` and `logout`. Existing auth/utility names and the nine approved auth filled silhouettes are unchanged. New filled task silhouettes use the same 24px grid; utilities fall back to their controlled Lucide outline when no filled silhouette is defined. Decorative icons remain hidden by default; localized visible labels belong to their consuming control, and explicitly standalone icons can receive caller-provided accessible semantics.
